Code final

last_word.c 
#include <unistd.h>

int    main(int argc, char **argv)
{
    if (argc != 2)
    {
        write(1, "\n", 1);
        return 0;
    }
    int i = 0;

    // 1. aller à la fin
    while (argv[1][i])
        i++;
    i--;

    // 2. skip espaces de fin (== || ==)
    while (i >= 0 && (argv[1][i] == ' ' || argv[1][i] == '\t'))
        i--;

    // 3. reculer au début du mot (!= && !=)
    while (i >= 0 && argv[1][i] != ' ' && argv[1][i] != '\t')
        i--;
    i++;

    // 4. afficher le mot
    while (argv[1][i] && argv[1][i] != ' ' && argv[1][i] != '\t')
    {
        write(1, &argv[1][i], 1);
        i++;
    }
    write(1, "\n", 1);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Quand utiliser || ou && avec les whitespaces ?
La règle magique...

Quand == → || (c'est un espace OU un tab). Quand != → && (c'est ni un espace NI un tab). Lois de De Morgan : NOT(A OR B) = (NOT A) AND (NOT B).

+
Pourquoi partir de la fin et pas du début ?
Dernier mot...

Si tu pars du début, tu dois parcourir toute la string et tracker le début du dernier mot en permanence. Depuis la fin, c'est plus direct : skip les espaces, puis recule jusqu'au prochain espace → tu as le début du dernier mot d'un coup.

+
Pourquoi le i++ après la boucle 3 ?
Où est i à la sortie de la boucle ?

La boucle 3 recule tant que c'est pas un espace. Quand elle sort, i est sur un espace (juste avant le mot) OU à -1. On fait i++ pour atterrir sur le premier char du mot. Sans ça, on afficherait l'espace en premier.

+
Pourquoi i >= 0 en premier dans les conditions ?
Court-circuit...

Le && fait du short-circuit : si la première condition est fausse, il ne teste pas la deuxième. Si tu mets argv[1][i] == ' ' && i >= 0, tu lis argv[1][-1] AVANT de vérifier i >= 0 → crash ou bug. Toujours mettre les checks de bounds en premier.

+
Que se passe-t-il avec " " (que des espaces) ?
Suis i...

Boucle 1 → i = 3, puis i-- → i = 2. Boucle 2 skip tous les espaces → i = -1. Boucle 3 : i >= 0 est faux, skip. i++ → i = 0. Boucle 4 : argv[1][0] = ' ', condition fausse, skip. Seul le write "\n" final s'exécute. Résultat : juste un newline. ✓

Pièges déjoués

3 pièges rencontrés sur cet exo

LOGIQUE
PIÈGE #1 — OR vs AND avec les whitespaces
✕while (c != ' ' || c != '\t') toujours vrai → boucle infinie
✓while (c != ' ' && c != '\t') les deux faux → pas un whitespace
Le piège : en français on dit "ni A ni B" mais en code c'est &&, pas ||. Un char est soit un espace, soit un tab, soit autre chose — avec ||, au moins une des négations est toujours vraie. Règle magique : == va avec ||, != va avec &&.
BOUNDS
PIÈGE #2 — i>=0 en dernier
✕argv[1][i] == ' ' && i >= 0
✓i >= 0 && argv[1][i] == ' '
Le piège : short-circuit du &&. C lit de gauche à droite. Si i = -1, l'ordre 1 lit argv[1][-1] avant de check i >= 0 → UB. Toujours les bounds checks avant l'accès mémoire.
SYNTAXE
PIÈGE #3 — argv[2] au lieu de argv[1]
✕argv[2][i] segfault
✓argv[1][i]
Le piège : argv[0] = nom du programme, argv[1] = premier argument réel. Si argc == 2, il n'y a qu'un seul argument utile et c'est argv[1]. argv[2] = NULL → crash.

Pattern réutilisable

Parcours depuis la fin + détection de mots

  1. Aller à la fin : while (str[i]) i++; i--;
  2. Skip les whitespaces de fin : while (i >= 0 && (str[i] == ' ' || str[i] == '\t')) i--;
  3. Reculer au début du mot : while (i >= 0 && str[i] != ' ' && str[i] != '\t') i--;
  4. Corriger : i++ (on était un cran trop loin)
  5. Afficher le mot : while (str[i] && str[i] != ' ' && str[i] != '\t') write + i++
