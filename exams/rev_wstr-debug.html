Le bug du i qui ne recule pas

Tu avais 90% de la logique. Voici la pièce manquante, visualisée pas à pas.

01 / TON DIAGNOSTIC

Ton bug à l'exam

"J'arrivais à print le dernier mot, mais après je restais bloqué dessus."

Symptôme : le programme print le dernier mot encore et encore, ne s'arrête jamais ou affiche des trucs n'importe comment.

Cause : après avoir trouvé l'espace et printé le mot, ton i reste sur cet espace. Au tour suivant, ta boucle "recule jusqu'à un espace" trouve le même espace immédiatement (puisque argv[1][i] EST déjà l'espace).

02 / LA SOLUTION EN UNE LIGNE

Le fix : i-- après le print

Une seule instruction te séparait de la victoire.

✕ Sans le fix

04 / POURQUOI LE FIX MARCHE

Le rôle de chaque i qui bouge

Recul interne (étape B) — sert à trouver le DÉBUT du mot courant.
Il s'arrête PILE sur l'espace qui précède le mot (ou à -1).

i-- final (étape clef) — sert à PASSER DEVANT cet espace pour que le tour suivant puisse trouver un nouvel espace.
Sans lui, l'étape B au tour suivant trouve immédiatement le même espace (puisque i pointe dessus) → boucle infinie.

💡 Métaphore
Imagine que tu recules dans un couloir et que tu cherches des portes. Tu trouves une porte (l'espace), tu lis le nom du locataire (le mot après). Maintenant pour trouver la porte SUIVANTE, tu dois continuer à reculer (i--), pas rester planté devant celle que tu viens de voir.
05 / CODE COMPLET

La version finale, dans ton style

3 variables (i, j, end), zéro malloc, walk in-place.

rev_wstr.c 
#include <unistd.h>

int	main(int argc, char **argv)
{
  if (argc != 2)
  {
    write(1, "\n", 1);
    return 0;
  }
  int i = 0;
  while (argv[1][i])
    i++;
  i--;
  int end;
  int j;
  while (i >= 0)
  {
    end = i;
    while (i >= 0 && argv[1][i] != ' ' && argv[1][i] != '\t')
      i--;
    j = i + 1;
    while (j <= end)
    {
      write(1, &argv[1][j], 1);
      j++;
    }
    if (i >= 0)
      write(1, " ", 1);
    i--;  // ⚡ LE FIX
  }
  write(1, "\n", 1);
  return 0;
}
