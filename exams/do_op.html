Code final

Compile avec -Wall -Wextra -Werror, tous tests OK

do_op.c 
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>

int main(int argc, char **argv)
{
    if (argc != 4)
    {
        write(1, "\n", 1);
        return 0;
    }
    int a = atoi(argv[1]);
    int b = atoi(argv[3]);
    if (argv[2][0] == '+')
        printf("%d\n", a + b);
    else if (argv[2][0] == '-')
        printf("%d\n", a - b);
    else if (argv[2][0] == '*')
        printf("%d\n", a * b);
    else if (argv[2][0] == '/')
        printf("%d\n", a / b);
    else if (argv[2][0] == '%')
        printf("%d\n", a % b);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
argc vaut combien pour ./do_op "1" "+" "2" ?
Le nom du programme compte...

argc = 4. Le nom du programme (argv[0] = "./do_op") compte toujours comme premier argument. Donc 3 "vrais" arguments = argc == 4.

+
Pourquoi argv[2][0] et pas argv[2] ?
Quel est le type de argv[2] ?

argv[2] est un char * (une string). On ne peut pas comparer une string avec == en C (ça compare les adresses). argv[2][0] est un char, qu'on peut comparer avec '+' etc.

+
Pourquoi printf("%d\n") et pas printf("%d") + write("\n") ?
Buffer...

printf bufferise (attend avant d'afficher), write écrit directement. Si on mélange, le \n de write sort avant le nombre de printf. Règle : ne jamais mélanger les deux dans le même programme.

+
Pourquoi on peut utiliser write pour le cas argc != 4 sans problème ?
return 0...

Parce qu'on fait return 0 juste après. Le programme s'arrête là, donc on n'arrive jamais aux printf. Pas de mélange = pas de problème de buffer.

Pièges déjoués

2 pièges rencontrés sur cet exo

SYNTAXE
PIÈGE #1 — #include manquant
✕write(1, "\n", 1); sans #include <unistd.h>
✓#include <unistd.h> en haut du fichier
Le piège : write est dans <unistd.h>, pas dans <stdio.h>. Sans l'include, -Werror refuse de compiler ("implicit declaration").
I/O
PIÈGE #2 — Mélanger printf et write
✕printf("%d", n); write(1, "\n", 1);
✓printf("%d\n", n);
Le piège : printf = bufferé (attend), write = direct. Le \n sort avant le nombre → "\n56088" au lieu de "56088\n". Toujours garder le \n dans le printf.

Pattern réutilisable

Programme avec arguments en ligne de commande

  1. Vérifier argc — toujours en premier, gérer le cas d'erreur et return
  2. Convertir les arguments string en int avec atoi(argv[n])
  3. Lire un char dans un argument : argv[n][0] (premier caractère de la string)
  4. Chaîne de if/else if pour dispatch selon l'opérateur
  5. Afficher avec printf("%d\n", result) — le \n dedans
