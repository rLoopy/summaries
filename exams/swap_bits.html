Flashcards

Réponds dans ta tête AVANT de cliquer

+
Qu'est-ce qu'un "nibble" ?
Demi-byte...

Un nibble = 4 bits = la moitié d'un byte. Un byte (8 bits) contient donc 2 nibbles : le haut (bits 7-4) et le bas (bits 3-0). Chaque nibble représente exactement un chiffre héxa (0-F).

+
Que fait octet >> 4 ?
Déplacer le nibble haut...

Décale l'octet de 4 positions vers la droite. Le nibble haut se retrouve en position basse, le nibble bas est perdu (sort à droite), les 4 bits de gauche sont remplis par des zéros. 11110000 >> 4 = 00001111.

+
Que fait octet << 4 ?
Déplacer le nibble bas...

Décale l'octet de 4 positions vers la gauche. Le nibble bas passe en position haute. Quand on retourne unsigned char, les bits qui débordent à gauche sont tronqués. 00001111 << 4 = 11110000.

+
Pourquoi | entre les deux ?
Fusionner deux motifs...

Après >> 4, seul le nibble bas du résultat est rempli. Après << 4, seul le nibble haut. Les deux résultats ont des zones complémentaires (aucun bit en commun) → le OR les fusionne sans conflit. + marcherait aussi ici.

+
Pourquoi pas besoin de boucle ?
Symétrie du problème...

Le swap de nibbles est une transformation globale symétrique. Deux shifts (un à droite, un à gauche) déplacent chacun la moitié du byte dans sa nouvelle position. Un simple OR fusionne les deux moitiés — aucun traitement bit-par-bit nécessaire.

Pièges déjoués

4 pièges — chaque carte = une leçon gravée

UNSIGNED
PIÈGE #1
✕char octet
✓unsigned char octet
Le piège : char est souvent signé. Le right shift d'un nombre signé négatif fait du "sign extension" (remplit avec des 1, pas des 0) → pollue le résultat. unsigned char garantit un remplissage par zéros.
PARENTHÈSES
PIÈGE #2
✕return octet >> 4 | octet << 4;
✓return ((octet >> 4) | (octet << 4));
Le piège : en C, >> et << ont une priorité supérieure à |, donc le code SANS parenthèses fonctionne aussi. Mais les parenthèses rendent l'intention explicite et évitent les doutes en peer-eval.
SHIFT COUNT
PIÈGE #3
✕(octet >> 8) | (octet << 8)
✓(octet >> 4) | (octet << 4)
Le piège : shifter de 8 sur un unsigned char (8 bits) est Undefined Behavior en C (shift >= largeur du type). Pour swap de nibbles : exactement 4.
OVERFLOW
PIÈGE #4
✕0xFF << 4 va overflow ?
✓Non, integer promotion vers int
Le piège : en C, les opérandes d'un shift sont promus à int avant l'opération. Donc 0xFF << 4 = 0xFF0 (en int, 12 bits utilisés). Quand on retourne en unsigned char, les bits > 8 sont tronqués. Résultat correct, aucun UB.
4

Pattern réutilisable

Shift + OR — fusion de deux motifs disjoints en une ligne

  1. Extraire le nibble haut : octet >> 4 → se retrouve en bas (bits 3-0)
  2. Extraire le nibble bas : octet << 4 → se retrouve en haut (bits 7-4)
  3. Fusionner les deux avec | — zones disjointes, aucun conflit
  4. Retourner le résultat (promotion int → unsigned char tronque automatiquement)
PATTERN SHIFT + OR = FUSION
swap_bits — swap nibbles via >>4 | <<4
rotate_bits — rotation circulaire via >>n | <<(8-n)
set/clear bit — x | (1 << n) pour activer
mask range — combiner plusieurs masques avec |
Principe — deux motifs aux zones disjointes peuvent se fusionner avec | sans interférer. Très efficace.

ALTERNATIVE — Arithmétique
unsigned char swap_bits(unsigned char octet) { return ((octet / 16) + (octet * 16)); // ou : (octet / 16) | (octet % 16 * 16); }
Strictement équivalent : /16 ≡ >>4, *16 ≡ <<4
Moins idiomatique en C, mais ça marche
Risque d'overflow visible si mal traité (le * 16 peut dépasser 255)

Exercices de transfert

Même pattern, exo différent — solidifie l'apprentissage

CHALLENGE 1
rotate_bits
Généralisation de swap_bits : rotation circulaire de n positions. Les bits qui sortent d'un côté rentrent par l'autre. Swap_bits = rotate avec n = 4.
unsigned char rotate_bits(unsigned char octet, int n);
Indice : (octet >> n) | (octet << (8 - n)). Exactement swap_bits quand n vaut 4.
CHALLENGE 2
reverse_bits
Inverser les 8 bits d'un byte. Nécessite une boucle cette fois — chaque bit doit aller à sa position opposée. Le pattern "shift + OR" reste, mais appliqué bit par bit.
unsigned char reverse_bits(unsigned char octet);
// 00100110 → 01100100
Indice : boucle 8 fois, res = res*2 + octet%2; octet /= 2; (arithmétique) ou res = (res<<1) | (octet&1); octet >>= 1; (bitwise).
CHALLENGE 3
split_nibbles
Extraire séparément le nibble haut et le nibble bas en deux valeurs. Utile pour décoder des formats compacts (ex: date stockée en BCD).
high = octet >> 4;
low = octet & 0x0F;
Indice : & 0x0F (ou & 15) masque les 4 bits hauts à 0 et garde les 4 bits bas.
