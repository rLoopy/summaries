Code final

ft_strdup.c 
#include <stdlib.h>

char	*ft_strdup(char *src)
{
	int i = 0;
	while (src[i])
		i++;
	char *dup = malloc(i + 1);
	int j = 0;
	while (src[j])
	{
		dup[j] = src[j];
		j++;
	}
	dup[j] = '\0';
	return (dup);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Pourquoi malloc(i+1) et pas malloc(i) ?
Pense au caractère de fin...

Le +1 est pour le '\0' terminal. i vaut la longueur de la string sans ce null byte, donc il faut un octet supplémentaire pour le stocker.

+
Que fait malloc ?
Allocation dynamique...

Alloue un bloc mémoire de n octets sur le tas (heap) et retourne un pointeur void * vers ce bloc. En cas d'échec, retourne NULL.

+
Quel header faut-il pour malloc ?
Pas stdio.h...

stdlib.h — c'est là que vivent malloc, free, atoi. Sans ce header, warning ou erreur de compilation garantis.

+
Que se passe-t-il si on oublie dup[j] = '\0' ?
La string est-elle validée ?

La string n'est pas terminée. Les fonctions comme printf ou strlen liront au-delà du bloc alloué jusqu'à trouver un '\0' aléatoire → comportement indéfini, crash possible.

+
Que retourne ft_strdup("") ?
String vide — trace mentalement...

Un pointeur vers un bloc alloué contenant juste '\0'. La boucle while(src[i]) ne s'exécute pas, i reste à 0, donc malloc(1) puis dup[0] = '\0'.

Pièges déjoués

4 pièges — chaque carte = une leçon gravée

NULL BYTE
PIÈGE #1
✕malloc(i) // oubli du +1
✓malloc(i + 1)
Le piège : i contient la longueur sans le '\0'. Si on alloue juste i octets, il n'y a pas de place pour le terminateur → overflow, comportement indéfini.
TYPE
PIÈGE #2
✕char dup; // pas un pointeur !
✓char *dup = malloc(i + 1);
Le piège : malloc retourne un void *. Il faut déclarer char *dup pour recevoir ce pointeur. Un simple char dup ne compile pas et perd l'adresse allouée.
TERMINATEUR
PIÈGE #3
✕// oubli de dup[j] = '\0'
✓dup[j] = '\0'; // après la boucle
Le piège : la boucle s'arrête quand src[j] == '\0' sans le copier. Il faut explicitement poser le terminateur après la boucle de copie.
HEADER
PIÈGE #4
✕// pas de #include <stdlib.h>
✓#include <stdlib.h>
Le piège : sans stdlib.h, le compilateur ne connaît pas la signature de malloc. Sur des archis 64 bits, cela peut causer un crash car le retour est traité comme un int (32 bits) au lieu d'un pointeur (64 bits).
4

Pattern réutilisable

malloc + copie manuelle — base de ft_strjoin, ft_substr, ft_split

  1. Calculer la longueur avec while(src[i]) i++ — i vaut le nombre de chars sans le '\0'
  2. Allouer avec malloc(i + 1) — le +1 est toujours pour le null byte, sans exception
  3. Copier char par char avec un index j : dup[j] = src[j]; j++;
  4. Poser le terminateur après la boucle : dup[j] = '\0';
  5. Retourner dup
OÙ RÉUTILISER CE PATTERN
ft_strjoin — malloc(len1 + len2 + 1), copier les deux strings à la suite
ft_substr — malloc(len + 1), copier uniquement la sous-string voulue
ft_strdup robuste — ajouter if (!dup) return NULL; juste après le malloc
ft_split — malloc pour chaque mot + tableau de pointeurs
