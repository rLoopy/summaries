Code final

Compile avec -Wall -Wextra -Werror, tous tests OK

is_power_of_2.c 
int	is_power_of_2(unsigned int n)
{
	if (n == 0)
		return (0);
	while (n > 1)
	{
		if (n % 2 != 0)
			return (0);
		n = n / 2;
	}
	return (1);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Qu'est-ce qu'une puissance de 2 ?
Pense à la série 1, 2, 4, 8...

Un nombre obtenu en multipliant 2 par lui-même : 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024... C'est 2 à la puissance n (20=1, 21=2, 22=4, etc.)

+
Comment vérifier qu'un nombre est une puissance de 2 avec une boucle ?
Pense au chemin inverse de la multiplication...

Diviser par 2 tant que c'est pair (n%2==0). Si on arrive à 1 → oui, c'est une puissance de 2. Si on tombe sur un nombre impair avant → non.

+
Pourquoi traiter n == 0 à part ?
Que ferait la boucle si n vaut 0 ?

0 n'est pas une puissance de 2, mais la boucle while(n>1) ne s'exécuterait pas (0>1 est faux) et on retournerait 1 par erreur. Le if (n == 0) return 0; empêche ce faux positif.

+
Que vaut 20 ?
Tout nombre à la puissance 0...

1. Donc is_power_of_2(1) doit retourner 1. C'est ce qui se passe : la boucle while(1>1) ne s'exécute pas, et on retourne 1 directement.

+
Que fait n % 2 ?
Le modulo c'est le reste de...

Le reste de la division par 2. Si c'est 0 → n est pair. Si c'est 1 → n est impair. On l'utilise pour vérifier que n est divisible par 2 à chaque étape.

+
Existe-t-il un one-liner bitwise ?
Astuce avec & ...

Oui : return (n > 0 && (n & (n - 1)) == 0); Mais la version boucle est plus intuitive et suffit largement pour l'exam. Ne l'utilise que si tu la comprends vraiment.

Pièges déjoués

4 pièges — chaque carte = une erreur à ne plus jamais faire

SÉCURITÉ
PIÈGE #1 — Oublier n == 0
✕// pas de check pour 0
✓if (n == 0) return (0);
Le piège : Sans ce check, la boucle while(n>1) est sautée et on retourne 1 pour n=0. Faux positif !
BOUCLE
PIÈGE #2 — n/1 au lieu de n/2
✕n = n / 1;
✓n = n / 2;
Le piège : n / 1 = n — la valeur ne change jamais, boucle infinie. Bien diviser par 2.
LOGIQUE
PIÈGE #3 — Confondre % et /
✕n % 2 → divise la valeur ?
✓% = reste (pair/impair) · / = descend la valeur
Le piège : % (modulo) donne le reste — sert à checker si c'est pair. / (division) descend la valeur — sert à avancer vers 1. Deux rôles différents.
INIT
PIÈGE #4 — Oublier que 1 est 2&sup0;
✕is_power_of_2(1) → 0 (faux)
✓is_power_of_2(1) → 1 (2&sup0; = 1)
Le piège : 1 = 20, c'est bien une puissance de 2. La boucle while(n>1) gère ça : 1 > 1 est faux, donc on retourne 1.

Pattern réutilisable

Vérification par division successive — puissance de 3, de 5, facteurs premiers...

  1. Traiter le cas n == 0 en premier — 0 n'est jamais une puissance de quoi que ce soit
  2. Tant que n > 1, vérifier que n est divisible par le facteur (ici 2)
  3. Si le reste n'est pas 0 → return 0 immédiatement (pas la peine de continuer)
  4. Sinon, diviser n par le facteur pour descendre vers 1
  5. Si on sort de la boucle → n vaut 1 → return 1
LE SQUELETTE GÉNÉRIQUE
int  is_power_of_X(unsigned int n, int x)
{
    if (n == 0)
        return (0);
    while (n > 1)
    {
        if (n % x != 0)    // pas divisible ?
            return (0);
        n = n / x;             // descend vers 1
    }
    return (1);              // arrivé à 1 = puissance de x
}
