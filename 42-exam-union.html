union.c 
#include <unistd.h>

int main(int argc, char **argv)
{
	if (argc != 3)
	{
		write(1, "\n", 1);
		return 0;
	}
	int i = 0;
	int j = 0;
	int found = 0;
	while (argv[1][i])
	{
		j = 0;
		found = 0;
		while (j < i)
		{
			if (argv[1][j] == argv[1][i])
				found = 1;
			j++;
		}
		if (found == 0)
			write(1, &argv[1][i], 1);
		i++;
	}
	i = 0;
	while (argv[2][i])
	{
		j = 0;
		found = 0;
		while (argv[1][j])
		{
			if (argv[1][j] == argv[2][i])
				found = 1;
			j++;
		}
		j = 0;
		while (j < i)
		{
			if (argv[2][j] == argv[2][i])
				found = 1;
			j++;
		}
		if (found == 0)
			write(1, &argv[2][i], 1);
		i++;
	}
	write(1, "\n", 1);
	return 0;
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Pourquoi 2 phases (s1 puis s2) ?
Ordre d'apparition...

Le sujet exige l'ordre d'apparition en ligne de commande. Donc on traite argv[1] en premier (ses chars sortent en premier), puis argv[2]. Fusionner les deux boucles dans une seule casserait l'ordre naturel.

+
Pourquoi while (j < i) et pas while (argv[1][j]) ?
Se comparer à soi-même...

On veut regarder derrière soi, pas parcourir toute la string. Avec while (argv[1][j]), on irait jusqu'au \0 → à un moment j == i → on compare s1[i] avec s1[i] → found = 1 toujours → on skip TOUT. while (j < i) s'arrête strictement avant le char courant.

+
Pourquoi 2 boucles internes pour la phase s2 ?
Deux "vus déjà"...

Un char de s2 a 2 raisons possibles d'être "déjà affiché" : (1) il apparait dans s1 entier (tous les chars uniques de s1 ont été write), (2) il apparait dans s2 avant l'index i (on l'a déjà vu dans s2). Les deux check partagent le même found — si au moins un le met à 1, on skip.

+
À quoi sert i = 0 entre les 2 phases ?
Reset de curseur...

Après la phase 1, i pointe au \0 de argv[1]. Avant de scanner argv[2], il faut remettre i à 0 pour repartir du début de s2. Sans ce reset, on sauterait le début de s2 ou on lirait hors limites.

+
Si s1 est vide "", que fait le code ?
Skip et continue...

Phase 1 : while (argv[1][0]) = while ('\0') = FAUX → boucle ignorée complètement. Phase 2 : scan argv[2] normalement, la boucle interne qui check s1 tourne zéro fois (car argv[1][0] == '\0'). Output final = s2 sans doublons. Ça marche automatiquement, pas besoin de cas spécial.

Pièges déjoués

4 pièges — chaque carte = une leçon gravée

WHILE (j < i)
PIÈGE #1
✕while (argv[1][j]) // compare s1[i] avec s1[i] aussi
✓while (j < i) // s'arrête AVANT i
Le piège : si on parcourt toute la string, à un moment j == i → on compare le char à lui-même → found = 1 toujours → on skip chaque char. j < i = "regarde derrière moi, pas moi".
RESET DE i
PIÈGE #2
✕// oublier i = 0 entre phase 1 et phase 2
✓i = 0; // APRÈS la phase 1, AVANT la phase 2
Le piège : après la phase 1, i pointe au \0 de s1. Sans reset, le while (argv[2][i]) part avec un i déjà grand → on saute le début de s2 ou on lit hors limites.
RESET DE found
PIÈGE #3
✕// found déclaré hors boucle, jamais reset
✓found = 0; // AU DÉBUT de chaque char à traiter
Le piège : si found n'est pas remis à 0 au début de chaque itération externe, une fois qu'il passe à 1 à cause d'un doublon, il reste à 1 pour tous les chars suivants → on skip tout.
RESET DE j
PIÈGE #4
✕// j pas reset entre les 2 boucles internes de phase 2
✓j = 0; // AVANT la 2ème boucle interne
Le piège : après la boucle qui scan s1 entier, j pointe au \0 de s1. Si on enchaine avec while (j < i) sans reset, j est déjà > i → la boucle ne tourne pas → doublons dans s2 non détectés.

Pattern réutilisable

Double while + flag — dans la famille de ft_strcspn

  1. Phase 1 (s1) : while argv[1][i] — pour chaque char, reset j=0, found=0, scan j < i, si doublon found=1, write si found==0
  2. Reset i = 0 entre les 2 phases
  3. Phase 2 (s2) : while argv[2][i] — reset j=0, found=0
  4. Scan s1 entier (while argv[1][j]) → si présent, found=1
  5. Reset j=0, scan s2 avant i (while j < i) → si présent, found=1
  6. Write si found==0. Après le while principal : write \n
FAMILLE DOUBLE WHILE + FLAG
ft_strcspn — scan reject pour chaque char de s
union — scan passe précédent pour détecter doublons
inter — 2 flags (doublon + présence dans s2)
search — flag "trouvé" réutilisable pour n'importe quel contains
Clé — le flag est reset à 0 au début de chaque traitement, monté à 1 si trouvé, testé avant action

Exercices de transfert

CHALLENGE 1
inter
Afficher les chars présents dans s1 ET s2, dans l'ordre de s1, sans doublons. 2 flags au lieu d'1 : dupe (déjà vu dans s1 avant) + in_s2 (existe dans s2). Condition : dupe==0 && in_s2==1.
// "padinton" + "paqefwtdjety…" → "padinto"
Indice : 1 seule phase (que s1), 2 boucles internes scannent s1 avant i et s2 entier.
CHALLENGE 2
ft_strcspn (révision)
Le parent de union. Compter les caractères de s AVANT le premier qui appartient à reject. Même double while + flag mais on incrémente un compteur au lieu de write.
size_t ft_strcspn(const char *s, const char *reject);
Indice : flag trouvé passe à 1 dès qu'un char de s[i] est dans reject → return i.
CHALLENGE 3
remove_duplicates (in-place)
Prendre une string et en retourner une version sans doublons (just la phase 1 d'union, mais sur une seule string). Très utile pour normaliser une entrée.
// "aabbccdd" → "abcd"
Indice : recopie exacte de la phase 1 d'union. Tu sais déjà le faire.
