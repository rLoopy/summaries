reverse_bits.c 
unsigned char	reverse_bits(unsigned char octet)
{
	int		i = 8;
	unsigned char	res = 0;

	while (i > 0)
	{
		res = res * 2 + (octet % 2);
		octet = octet / 2;
		i--;
	}
	return (res);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Que fait x * 2 en binaire ?
Pense aux puissances de 2...

Décale tous les bits d'un cran vers la gauche. Strictement équivalent à x << 1. La position 0 est remplie par un zéro. 5 * 2 = 10 ; en binaire 0101 → 1010.

+
Que fait x % 2 en binaire ?
Dernier chiffre...

Extrait le bit de poids faible (LSB, tout à droite). Résultat toujours 0 ou 1. Strictement équivalent à x & 1. C'est le chiffre des unités en base 2.

+
Pourquoi res * 2 AVANT d'ajouter le bit ?
Libérer la place...

Le * 2 décale les bits déjà présents à gauche et libère la position 0. Ensuite on ajoute le nouveau bit à cette place. Si on inversait l'ordre, on écraserait un bit sur deux.

+
Pourquoi + et pas | ici ?
Aucun overlap...

Après res * 2, le bit de position 0 de res est garanti à 0. Ajouter 0 ou 1 via + ne fait pas de retenue et produit le même résultat que |. Les deux marchent ici. | serait plus "robuste" si un jour le bit 0 était non-nul.

+
Équivalence arithmétique ↔ bitwise ?
3 paires magiques...

x * 2 = x << 1 — x / 2 = x >> 1 — x % 2 = x & 1. Donc la version bitwise : res = (res << 1) | (octet & 1); octet >>= 1; — strictement identique.

Pièges déjoués

4 pièges — chaque carte = une leçon gravée

ORDRE
PIÈGE #1
✕res = res + (octet % 2); res = res * 2;
✓res = res * 2 + (octet % 2);
Le piège : si on multiplie après avoir ajouté le bit, on décale aussi le nouveau bit → résultat faux. Toujours : shift d'abord, bit ensuite.
UNSIGNED
PIÈGE #2
✕char octet / signed int
✓unsigned char octet
Le piège : sur un char signé, la division par 2 d'une valeur négative arrondit vers 0 (ou pas, selon l'implémentation). Avec le MSB à 1, le comportement diverge. Toujours unsigned pour la manip bitwise/arithmétique bit-par-bit.
ITERATIONS
PIÈGE #3
✕while (octet > 0) // s'arrête trop tôt
✓int i = 8; while (i > 0) { ... i--; }
Le piège : while (octet > 0) s'arrête dès qu'octet devient 0 → les zéros de poids fort ne sont jamais "poussés" dans res. Il faut exactement 8 itérations, peu importe la valeur.
RETURN
PIÈGE #4
✕// oublier return res
✓return (res);
Le piège : la fonction doit retourner le byte inversé, pas l'afficher (c'est pas print_bits). Sans return, le comportement est Undefined Behavior (warning -Werror).

Pattern réutilisable

Pop LSB → push à gauche — construire un nouveau byte en inversant

  1. Initialiser res = 0, compteur i = 8
  2. Shift res à gauche : res * 2 (ou res << 1) — libère la position 0
  3. Extraire le bit de droite d'octet : octet % 2 (ou octet & 1)
  4. Ajouter le bit à res : res * 2 + (octet % 2) en une ligne
  5. Shift octet à droite : octet / 2 (ou octet >> 1) — prochain bit en position 0
  6. Répéter 8 fois, return (res)
ÉQUIVALENCE ARITHM ↔ BITWISE
x * 2 ≡ x << 1 — shift gauche
x / 2 ≡ x >> 1 — shift droite
x % 2 ≡ x & 1 — LSB
Intuition clé — le binaire c'est de l'arithmétique base 2. Si tu bloques sur les bits, passe par les maths : c'est strictement équivalent.
Pattern — pop un bit d'un côté, push de l'autre

Évolution du code

2 versions — de la version bitwise à la version arithmétique

VERSION 1 — Bitwise (joker 1)
unsigned char reverse_bits(unsigned char octet) { unsigned char res = 0; int i = 0; while (i < 8) { res = res << 1; res = res | (octet & 1); octet = octet >> 1; i++; } return (res); }
Correct mais utilise les opérateurs bitwise
"J'abandonne les bits" → l'étudiant bloque psychologiquement
VERSION FINALE — Arithmétique ✓
unsigned char reverse_bits(unsigned char octet) { int i = 8; unsigned char res = 0; while (i > 0) { res = res * 2 + (octet % 2); octet = octet / 2; i--; } return (res); }
L'étudiant a trouvé cette version seul (pas bitwise) ✓
Strictement équivalente : *2 ≡ <<1, /2 ≡ >>1, %2 ≡ &1
Compile -Wall -Wextra -Werror, tests 38/1/128/255/170 OK ✓
Intuition : bits = arithmétique base 2 (débloque le blocage psycho)

Exercices de transfert

Même pattern, exo différent — solidifie l'apprentissage

CHALLENGE 1
print_bits
Même structure de boucle (8 itérations, extraction bit par bit), mais au lieu de construire un byte résultat, tu écris chaque bit à l'écran. Plus simple : pas de res à construire.
void print_bits(unsigned char octet);
// 2 → affiche "00000010"
Indice : write(1, &c, 1) où c = ((octet >> i) & 1) + '0'.
CHALLENGE 2
swap_bits
Échanger les 4 bits hauts avec les 4 bits bas d'un byte. Pas de boucle : juste deux shifts et un OR. Le pattern "shift + OR" est ultra puissant quand les motifs sont disjoints.
unsigned char swap_bits(unsigned char octet);
// 11110000 → 00001111
Indice : (octet >> 4) | (octet << 4) — 1 ligne.
CHALLENGE 3
rotate_bits
Rotation circulaire de n positions. Les bits qui sortent d'un côté rentrent par l'autre (pas perdus comme un shift classique). Généralisation de swap_bits.
unsigned char rotate_bits(unsigned char octet, int n);
Indice : (octet >> n) | (octet << (8 - n)). Pour n = 4, c'est exactement swap_bits.

Checklist exam

Vérifie avant chaque submit

  • ☐ Param & return : unsigned char — jamais signed
  • ☐ Initialiser res = 0 avant la boucle
  • ☐ Exactement 8 itérations (ne pas utiliser while (octet > 0))
  • ☐ Ordre dans la boucle : shift res d'abord, ajouter bit, puis shift octet
  • ☐ res = res * 2 + (octet % 2) (arithm) ou res = (res << 1) | (octet & 1) (bitwise)
  • ☐ octet /= 2 (ou octet >>= 1) en fin de boucle
  • ☐ return (res); — pas d'oubli
  • ☐ Compile gcc -Wall -Wextra -Werror
  • ☐ Tester : 38→100, 1→128, 128→1, 0→0, 255→255
