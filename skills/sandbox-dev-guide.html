Code dans une Sandbox

Guide complet pour isoler ton environnement de dev avec Docker + Cursor sur Windows. Vibecode tranquille, ton PC reste propre.

🎯 TL;DR

Installe Docker Desktop + l'extension Dev Containers dans Cursor. Chaque projet tourne dans un container isolé. Si un package malveillant s'exécute, il reste enfermé dans le container — pas d'accès à tes mots de passe, wallets, cookies ou fichiers perso.

⚠️

Pourquoi c'est important ?

Quand tu vibeocodes, l'IA installe des packages, exécute des commandes, écrit des fichiers. Si un package est malveillant (supply chain attack), il a accès à tout ce qui est sur ta machine :

❌ Sans sandbox

Le malware accède à tes cookies Chrome, tes wallets crypto, tes SSH keys, tes API keys, tes fichiers perso, tes sessions Discord...

✅ Avec sandbox

Le malware est enfermé dans le container. Il voit que les fichiers du projet. Ton Windows est intact.

1

Installe Docker Desktop

Télécharge et installe depuis le site officiel. Au premier lancement, il te demande d'activer WSL 2 (tu l'as déjà).

# Vérifie que Docker tourne
docker --version
Docker version 27.x.x

# Vérifie WSL 2 backend
docker info | grep OSType
OSType: linux
2

Extension Dev Containers

Dans Cursor (ou VSCode), installe l'extension :

# Dans Cursor → Extensions → cherche :
Dev Containers
# Par Microsoft — identifiant :
ms-vscode-remote.remote-containers
3

Crée le fichier de config dans ton projet

À la racine de ton projet, crée un dossier .devcontainer/ avec deux fichiers :

# .devcontainer/devcontainer.json
{
  "name": "Dev Sandbox",
  "build": { "dockerfile": "Dockerfile" },
  "customizations": {
    "vscode": {
      "extensions": [
        "ms-vscode.cpptools"
      ]
    }
  },
  "postCreateCommand": "echo '✅ Sandbox prête !'"
}
# .devcontainer/Dockerfile
FROM debian:bookworm-slim

RUN apt-get update && apt-get install -y \
    gcc \
    make \
    valgrind \
    git \
    curl \
    python3 \
    nodejs \
    npm \
    && rm -rf /var/lib/apt/lists/*

# Un user non-root pour la sécurité
RUN useradd -ms /bin/bash dev
USER dev
WORKDIR /home/dev/project
4

Ouvre dans le container

Dans Cursor :

  • Ctrl+Shift+P
  • Tape "Reopen in Container"
  • Clique → attend 30 secondes
  • T'es dans la sandbox !

La prochaine fois ça sera instantané — Docker cache le build.

5

Vibecode normalement

Tout marche comme avant :

  • Terminal → dans le container
  • Fichiers → montés depuis ton projet
  • Extensions Cursor → fonctionnent
  • IA → exécute dans le container
  • npm/pip install → dans le container

La seule différence : rien ne touche ton Windows.

🎓

Template spécial 42

Pour tes projets 42, voici un Dockerfile optimisé :

# .devcontainer/Dockerfile (version 42)
FROM debian:bookworm-slim

RUN apt-get update && apt-get install -y \
    gcc \
    clang \
    make \
    valgrind \
    gdb \
    git \
    man-db \
    libc6-dev \
    && rm -rf /var/lib/apt/lists/*

# Compile flags style 42
ENV CFLAGS="-Wall -Wextra -Werror"

RUN useradd -ms /bin/bash dev
USER dev
WORKDIR /home/dev/project
🛡️

Règles d'or de la sandbox

  • Jamais d'API keys dans le container — utilise des env vars au lancement
  • Jamais monter tout le disque — seul le dossier du projet est partagé
  • User non-root dans le container — limite les dégâts
  • Recréer régulièrement le container — un doute ? docker compose down && docker compose up
  • Pas de navigateur dans le container — le malware ne peut pas voler tes cookies

🔒 Setup une fois, tranquille pour toujours

5 minutes de setup. Ensuite chaque projet tourne dans sa bulle. Tu vibeocodes sans stress, ton PC reste propre, tes secrets sont en sécurité. Drop le dossier .devcontainer/ dans chaque projet et c'est réglé.
