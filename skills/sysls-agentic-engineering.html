Less is More — N'installe rien

Les solutions tierces (skills, mémoire, subagents) qui marchent vraiment finissent toujours intégrées dans les produits officiels. Si OpenAI et Anthropic l'implémentent tous les deux → c'est utile. Sinon, c'est probablement du bruit. Mets juste à jour ton CLI de temps en temps et lis les release notes.

🧠

Le contexte est TOUT

Le context bloat est l'ennemi n°1. Chaque plugin, mémoire, skill mal nommée pollue le contexte de l'agent. Donne-lui EXACTEMENT l'info dont il a besoin, rien de plus. Un agent qui reçoit des recettes de cuisine quand tu lui demandes un poème va produire de la merde.

Sépare recherche et implémentation

❌ "Construis un système d'auth" → l'agent recherche toutes les options, son contexte se pollue, il hallucine.

✅ "Implémente JWT avec bcrypt-12, refresh token rotation, expiry 7 jours" → il sait exactement quoi faire.

Si tu ne connais pas les détails → fais une tâche de recherche séparée, décide, puis lance un agent frais pour implémenter.

Traite ton CLAUDE.md comme un répertoire logique IF-ELSE de où trouver le contexte selon le scénario. Il doit être barebones et ne contenir que les directions.
— @systematicls
🎭

Exploite la sycophantie au lieu de la subir

Les agents veulent te plaire. Si tu dis "trouve un bug", ils en inventeront un. Utilise des prompts neutres : "Parcours le code, suis la logique, rapporte tes observations."

# Système adversarial à 3 agents

Agent 1 — Bug-finder (sycophant)
  "+1 bug mineur, +5 moyen, +10 critique"
  → Trouve TOUS les bugs (même les faux)

Agent 2 — Adversarial
  "+score si réfute un bug, -2×score si tort"
  → Réfute agressivement les faux positifs

Agent 3 — Referee
  "+1 correct, -1 incorrect (vs ground truth)"
  → Tranche entre les deux → haute fidélité
✅

Les tests = milestone

"Ta tâche n'est PAS finie tant que ces X tests ne passent pas. Tu n'as PAS le droit de modifier les tests."

Les tests sont déterministes → l'agent sait exactement quand il a terminé. Combine avec des screenshots + vérification pour le frontend.

📜

Contracts, pas sessions 24h

Les sessions longues dérivent. À la place : 1 contrat par tâche, un stop-hook qui bloque la terminaison tant que le contrat n'est pas rempli. Orchestration layer qui crée de nouveaux contrats → agents frais à chaque fois.

📏

Rules = préférences

Quand tu vois l'agent faire un truc que t'aimes pas → ajoute une rule. Dis-lui de lire la rule AVANT de refaire cette action. Il ne le refera plus.

🧪

Skills = recettes

Tu veux contrôler COMMENT un problème est résolu ? Fais rechercher l'approche par l'agent, écris-la comme skill, corrige-la, puis référence-la dans le CLAUDE.md.

♻️

Le cycle magique : itère sans cesse

1. Commence barebones (juste le CLI)
2. Ajoute des rules quand tu vois un problème
3. Ajoute des skills quand tu veux contrôler une méthode
4. Quand la performance se dégrade → cleanup day : consolide, supprime les contradictions, demande à l'agent de simplifier
5. Ça redevient magique → retourne en 2.

C'est le même principe qu'un EA (executive assistant) : tu construis les préférences avec le temps, pas d'un coup.

🎯 Own the Outcome

Aucun agent n'est parfait. Tu délègues le design et l'implémentation, mais tu gardes la responsabilité du résultat. Strip tes dépendances, maîtrise le contexte, utilise rules et skills, et nettoie régulièrement. C'est tout le secret.
