Dans parse_args il y a 8 étoiles (et 1 esperluette &). Chacune fait un truc précis. On les prend une par une.

🎯 Ce que parse_args fait (big picture)

parse_args c'est le chef d'orchestre du parser. Elle fait pas de calcul elle-même, elle enchaîne les autres fonctions dans le bon ordre et gère les erreurs.

Son job en une phrase

Transformer les arguments bruts du terminal en un tableau d'ints validé et propre, prêt à être utilisé pour construire les piles.

Entrée : argc = 5 argv = ["./push_swap", "3", "1", "4", "2"] &n = (adresse d'une variable n dans main) ↓ parse_args() ↓ Sortie : retour : [3, 1, 4, 2] (un int *values tout neuf) n = 4 (écrit dans la variable de main via le pointeur)

Les 3 choses importantes qu'elle fait

  • 1Normalise l'entrée : que le user donne "3 1 4" ou 3 1 4, on produit le même résultat.
  • 2Valide chaque argument : format correct, pas d'overflow, pas de doublon.
  • 3Convertit les strings en vrais int dans un tableau alloué dynamiquement.

Son contrat (ce qu'elle promet)

  • OKEn cas de succès : renvoie un int * valide. Écrit le nb d'éléments dans *n.
  • KOEn cas d'erreur : renvoie NULL. Aucune mémoire ne fuit. Le caller affichera "Error" et exit.

💡 parse_args ne print jamais rien elle-même. Elle remonte juste les erreurs. C'est le principe de séparation des responsabilités : parse_args parse, main agit.

🧠 Il y a 2 sortes de * en C

Le même caractère * fait 2 choses différentes selon où il est. C'est ça qui rend les pointeurs confus. On doit toujours se demander : c'est dans une DÉCLARATION ou dans du CODE qui s'exécute ?

Type 1 : l'étoile dans une DÉCLARATION

Quand tu écris int *x; ou char **argv, l'étoile fait partie du type. Elle dit "cette variable est un pointeur".

int *x;type // x est une variable de type "int *" // c'est-à-dire : une boîte qui contient une adresse mémoire // (et pas un nombre).

Type 2 : l'étoile comme OPÉRATEUR (dans le code)

Quand tu écris *p = 42 ou if (*p == 0), l'étoile est un opérateur. Elle veut dire "va chercher la valeur à l'adresse contenue dans p".

int *p = &a; // p contient l'adresse de a *p = 42;deref // écris 42 à l'adresse contenue dans p (donc dans a)

Truc simple pour distinguer : si l'étoile est au moment où tu déclares la variable (à côté de son nom, dans un int/char/void etc.) → TYPE. Si elle est dans du code qui utilise une variable déjà déclarée → DEREF.

Il y a aussi & (esperluette)

L'inverse du *. &x veut dire "donne-moi l'ADRESSE de x". C'est comme ça qu'on obtient un pointeur vers quelque chose.

🔄 Le flow étape par étape (trace concrète)

Prenons l'appel parse_args(5, ["./push_swap","3","1","4","2"], &n). Voici ce qui se passe en interne :

Étape 1 (lignes 6-8) — tokeniser

tokens = tokenize(argc, argv); if (!tokens) return (NULL);

On transforme argv en un tableau de strings uniforme : ["3", "1", "4", "2", NULL]. Si tokenize a raté (malloc fail), on return NULL tout de suite — rien à free, on a rien alloué nous-même.

Étape 2 (lignes 9-14) — compter

*n = count_tokens(tokens); if (*n == 0) { free_tokens(tokens); return (NULL); }

On compte combien de strings (4 dans notre cas). On stocke dans *n (via l'output parameter). Si n vaut 0 (user a passé "" ou " ") → Error. On free les tokens qu'on a alloués, puis NULL.

Étape 3 (lignes 15-18) — convertir

values = convert_tokens(tokens, *n); free_tokens(tokens); if (!values) return (NULL);

convert_tokens alloue values et remplit avec [3, 1, 4, 2]. Si un token est invalide ou overflow, elle renvoie NULL.

⚠️ Note importante sur l'ordre : free_tokens(tokens) est appelé AVANT le check if (!values). Pourquoi ? Parce que dans tous les cas — succès ou échec de la conversion — on n'a plus besoin des strings. Les libérer dans tous les cas évite un leak.

Étape 4 (lignes à remplir, le TROU) — check doublons

/* TROU à toi */ if (has_duplicates(values, *n)) { free(values); return (NULL); }

Dernière vérification avant la victoire. Les ints sont valides individuellement, mais est-ce qu'il y en a 2 identiques ? Si oui → Error. Note qu'on free values (pas tokens, déjà free'd).

Étape 5 (ligne 19) — victoire

return (values);

Tout est OK. On renvoie values. *n a déjà été mis à jour à l'étape 2, donc le caller a tout ce qu'il faut.

Résumé visuel

parse_args(5, [...], &n) │ ├─ tokenize(...) → ["3","1","4","2",NULL] ✓ │ ├─ count_tokens(tokens) → 4 (*n = 4) │ ├─ convert_tokens(...) → [3,1,4,2] ├─ free_tokens(tokens) (memoire propre) │ ├─ has_duplicates(values, 4) → 0 (pas de doublon) │ └─ return values = [3,1,4,2]

💾 La discipline mémoire : qu'est-ce qu'on alloue / libère quand ?

Le sujet est strict : "Memory leaks will not be tolerated." Chaque malloc doit avoir un free correspondant, même quand on sort à cause d'une erreur.

Dans parse_args, on alloue 2 "choses"

  • 1tokens (alloué par tokenize → soit ft_split soit nos malloc + ft_strdup)
  • 2values (alloué par convert_tokens → un malloc)

Les règles à chaque point d'erreur

Si tokenize échoue : rien d'alloué, rien à free. return NULL; Si *n == 0 (tokens vides) : tokens alloué → free_tokens(tokens); return NULL; Si convert_tokens échoue : tokens encore en vie → free_tokens(tokens); values est NULL (pas alloué) → rien à free. return NULL; Si has_duplicates vrai (TROU) : tokens déjà free'd. values alloué → free(values); return NULL; Si tout OK : tokens déjà free'd. values vit → on le return, le caller aura la charge de free.

Le pattern à retenir

Avant CHAQUE return (NULL), demande-toi :
"Qu'est-ce que j'ai alloué jusqu'ici qui est encore vivant ?"
Et libère-le.

C'est le truc qui différencie un code qui compile d'un code qui passe le leak check en peer-eval.

🏷️ Les 5 étoiles de TYPE (déclarations)

Chaque étoile ajoute un cran d'indirection. Zéro étoile = valeur. Une étoile = pointeur vers valeur. Deux étoiles = pointeur vers pointeur.

int x → une valeur : [42] int *p → un pointeur : [0x100] → [42] (une adresse qui pointe sur un int) int **pp → double ptr : [0x200] → [0x100] → [42] (adresse qui pointe sur une adresse qui pointe sur un int)

Les 5 étoiles de type dans parse_args

  • L1int *parse_args(...)
    → La fonction retourne un int * (un pointeur sur int, c'est-à-dire un tableau d'ints).
  • L1char **argv
    → argv est un char ** : pointeur vers un pointeur sur char, donc un tableau de strings.
  • L1int *n
    → n est un int * : un pointeur vers un int (output parameter, on voit ça carte 5).
  • L3char **tokens
    → Variable locale, même type que argv (un tableau de strings).
  • L4int *values
    → Variable locale qui stockera un tableau d'ints (après malloc).

💡 Chacune de ces étoiles ne "fait" rien au runtime. Elles disent juste au compilateur "attention, cette variable c'est un pointeur, pas une valeur". Elles disparaissent une fois le code compilé.

🔓 Les 3 étoiles de DEREF (opérateurs)

Une étoile devant une variable (dans du code exécutable) veut dire "ouvre la boîte pointée et donne-moi ce qu'il y a dedans". Ou à gauche d'un = : "écris dans la boîte pointée".

Étoile #1 : *n = count_tokens(tokens); (ligne 9)

Ici *n est à gauche du =. Ça veut dire : "va à l'adresse contenue dans n, et écris ce qu'on te donne".

Avant la ligne 9 : variable de main : int n ═══ [???] (non initialisée) ↑ paramètre parse_args : int *n ═══ [&n] ─────┘ (contient l'adresse du n de main) Après *n = 4; : variable de main : int n ═══ [4] ✓ modifiée ↑ paramètre parse_args : int *n ═══ [&n] ─────┘

C'est le pattern "output parameter" : parse_args utilise l'étoile pour écrire dans la variable de l'appelant (main). Sans l'étoile, on écrirait juste dans une copie locale.

Étoile #2 : if (*n == 0) (ligne 10)

Ici *n est dans une expression qui lit. Ça veut dire : "va à l'adresse dans n, lis la valeur là-bas, compare-la à 0".

if (*n == 0)deref // │ // └── "suis le pointeur, lis la valeur" // équivaut à : "lis la valeur de n du caller"

Sans l'étoile, if (n == 0) comparerait l'adresse à 0 (checkerait si n est NULL). Pas du tout ce qu'on veut.

Étoile #3 : convert_tokens(tokens, *n) (ligne 15)

Pareil que l'étoile #2, mais utilisée pour passer la valeur à une autre fonction.

convert_tokens(tokens, *n);deref // │ // └── on passe la VALEUR (genre 4) // pas l'adresse.

La fonction convert_tokens a pour signature int *convert_tokens(char **tokens, int n). Son n est un simple int, pas un pointeur. Donc on doit lui passer une valeur, d'où le * pour déréférencer avant de passer.

🎯 Zoom : le pattern "output parameter"

C'est la technique qui explique pourquoi n est un int * au lieu d'un simple int. Elle permet à parse_args de retourner 2 valeurs (un tableau + un compteur).

Le problème

Une fonction C peut retourner qu'UNE seule valeur. Mais parse_args veut produire deux choses :

  • int *values : le tableau d'ints
  • int n : combien y en a

La solution : un pointeur qui sert de "canal de retour"

Le caller (main) donne à parse_args l'adresse d'une variable n qui lui appartient. parse_args écrit dedans via déréférencement.

// Côté main (le caller) : int n; // 1. variable locale (pas encore initialisée) int *values = parse_args(argc, argv, &n); // 2. on passe l'ADRESSE de n // ↑ // & = "adresse de" // Côté parse_args (la fonction) : int *parse_args(int argc, char **argv, int *n) { // n reçoit l'adresse passée ... *n = count_tokens(tokens); // 3. écrit dans le n de main ... } // Retour côté main : // n contient maintenant la valeur écrite par parse_args

Mental model : le parking avec la clef

Imagine que n c'est une voiture dans le parking de main. Main donne à parse_args la clef de la voiture (&n). parse_args utilise la clef (*n) pour ouvrir le coffre et y déposer "4". Main retrouve sa voiture avec "4" dans le coffre.

main : ┌───── n ────────┐ la "voiture" de main │ [?] │ └───────────────┘ ↑ │ (&n) ← main donne l'adresse │ parse_args : ┌── int *n ──────┐ │ [@] │ reçoit l'adresse (= la clef) └───────────────┘ │ │ *n = 4 → va à l'adresse, écrit 4 ▼ main : ┌───── n ────────┐ │ [4] │ maintenant n vaut 4 └───────────────┘
