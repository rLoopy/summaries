CHAPITRE 08

Le Makefile

NAME, static pattern rule, et tout ce qui compile

§8.1 — Le Makefile complet

NAME    = server client
CC      = cc
CFLAGS  = -Wall -Wextra -Werror -I includes
HEADER  = includes/minitalk.h
OBJS    = src/server.o src/client.o

all: 

: %: src/%.o
	  -o  $<

src/%.o: src/%.c 
	  -c $< -o 

clean:
	rm -f 

fclean: clean
	rm -f 

re: fclean all

.PHONY: all clean fclean re

§8.2 — NAME avec une liste

Au lieu d avoir un seul nom de binaire, on en a 2. Astuce :

NAME = server client

NAME est une variable Make qui contient "server client" (2 mots). Quand on écrit , ça expand en "server client".

all: devient donc all: server client — pour faire all, on doit construire server ET client.

§8.3 — Static pattern rule

: %: src/%.o
	  -o  $<
★ Comment ça marche
C est une static pattern rule. La syntaxe est :
cibles: pattern_match: pattern_prereq

Pour chaque cible dans NAME (server, client), Make remplace % par le nom de la cible :
  • Cible "server" → match % = "server" → prerequis = src/server.o
  • Cible "client" → match % = "client" → prerequis = src/client.o
La recette est appliquée pour chacune avec = nom de la cible, $< = premier prérequis.

Sans static pattern rule, on aurait dû écrire 2 règles séparées :

server: src/server.o
	$(CC) $(CFLAGS) -o server src/server.o
client: src/client.o
	$(CC) $(CFLAGS) -o client src/client.o

C est plus verbeux. Le static pattern rule c est plus DRY.

§8.4 — Compilation des .o

src/%.o: src/%.c 
	  -c $< -o

Règle générique : pour fabriquer src/X.o, on a besoin de src/X.c ET du header. La recette compile le .c en .o.

★ Pas de relinking inutile
La dépendance sur fait que si le header change, tous les .o sont recompilés. Si rien n a changé, make ne refait rien — il compare les timestamps. C est la base d un Makefile efficace.

§8.5 — Les règles de cleanup

clean:
	rm -f $(OBJS)

fclean: clean
	rm -f $(NAME)

re: fclean all
  • clean : supprime les .o
  • fclean : appelle clean puis supprime les binaires
  • re : appelle fclean puis all → recompile tout depuis zéro

§8.6 — .PHONY

.PHONY: all clean fclean re

.PHONY dit à Make que ces cibles ne sont pas des fichiers mais des commandes. Sans ça, si tu créais un fichier nommé "all" dans le dossier, Make penserait que la cible all est à jour et ne ferait rien.

§8.7 — Récap

★ Points clés
  • NAME contient une liste (server client) pour fabriquer 2 binaires
  • Static pattern rule évite de répéter la règle de link
  • Dépendance sur HEADER = pas de relinking inutile
  • 4 règles obligatoires : all, clean, fclean, re
  • .PHONY pour les cibles qui ne sont pas des fichiers
  • rule présente — exigence stricte du PDF
