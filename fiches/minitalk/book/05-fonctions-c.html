CHAPITRE 05

Les fonctions C utilisées

kill, sigaction, pause, write, et les autres

§5.1 — kill(pid, sig)

Malgré son nom, kill ne tue rien. C est juste la fonction pour envoyer un signal à un process.

#include <signal.h>

int kill(pid_t pid, int sig);

// Retourne 0 si succès, -1 si erreur

Côté client minitalk :

kill(server_pid, SIGUSR1);  // envoie le bit 0
kill(server_pid, SIGUSR2);  // envoie le bit 1
★ Attention au PID
Si pid = 0, le signal est envoyé à tous les process du même group. Si pid = -1, à tous les process accessibles. C est pour ça qu on valide le PID avant.

§5.2 — L astuce kill(pid, 0)

Le signal 0 est spécial : il ne déclenche aucun handler, il ne tue rien. Mais il fait toutes les vérifications de permission.

kill(pid, 0);

// Retour :
//   0  → process existe et on peut lui parler
//  -1  → ESRCH : process n existe pas
//        EPERM : on n a pas le droit
★ L idiome standard
kill(pid, 0) est l idiome standard pour valider qu un PID est joignable avant d envoyer un vrai signal. C est ce qu on fait dans check_pid.

§5.3 — struct sigaction

C est la structure POSIX qui décrit comment gérer un signal. On la remplit, puis on l enregistre via sigaction().

struct sigaction sa;

sa.sa_handler   // pointeur vers la fonction handler (void f(int))
sa.sa_sigaction // version avancée avec siginfo_t (PID du sender, etc.)
sa.sa_mask      // signaux à BLOQUER pendant l exécution du handler
sa.sa_flags     // options : SA_RESTART, SA_SIGINFO, etc.

Dans notre server :

struct sigaction sa;

sigemptyset(&sa.sa_mask);          // vide le masque
sigaddset(&sa.sa_mask, SIGUSR1);    // ajoute SIGUSR1 au masque
sigaddset(&sa.sa_mask, SIGUSR2);    // ajoute SIGUSR2 au masque
sa.sa_flags = SA_RESTART;
sa.sa_handler = handle_signal;

sigaction(SIGUSR1, &sa, NULL);      // enregistre pour SIGUSR1
sigaction(SIGUSR2, &sa, NULL);      // et pour SIGUSR2
★ sa_mask
Quand le handler tourne, par défaut SEUL le signal qui l a déclenché est bloqué. Avec sigaddset, on bloque AUSSI l autre signal. Pour minitalk c est crucial : un SIGUSR2 ne doit pas interrompre un handler SIGUSR1 (race condition sur les variables static c et bit_count).

§5.4 — pause()

Bloque le process jusqu à réception d un signal. Quand un signal arrive, le handler s exécute, puis pause() retourne.

#include <unistd.h>

int pause(void);

// Toujours retourne -1 (errno = EINTR) après réception

Dans notre server :

while (1)
    pause();

Le server boucle indéfiniment dans pause(). Chaque signal le réveille, le handler tourne, puis pause() est ré-appelé.

§5.5 — usleep()

Suspend le process pour N microsecondes (1 µs = 1 millionième de seconde).

#include <unistd.h>

int usleep(useconds_t usec);

Dans notre client : usleep(700) = 0.7 milliseconde de pause après chaque signal envoyé.

★ Pourquoi 700 ?
Trade-off vitesse / fiabilité. Trop court (ex: 100) → signaux perdus (Linux ne queue pas). Trop long → trop lent (limite sujet : 100 chars en moins d 1 seconde, soit 1.25 ms par bit max). 700 µs c est calibré expérimentalement pour ~676ms pour 100 chars avec ~90% fiabilité.

§5.6 — write()

Écrit N bytes sur un file descriptor. C est l outil de sortie le plus bas niveau de Linux.

#include <unistd.h>

ssize_t write(int fd, const void *buf, size_t count);

// fd : 0 = stdin, 1 = stdout, 2 = stderr

Dans notre code :

write(1, &c, 1);                 // affiche 1 char sur stdout
write(1, "Server PID: ", 12);    // affiche le label
write(2, "Error...", 8);         // erreur sur stderr
★ write vs printf
write est async-signal-safe — on peut l utiliser dans un handler sans risque. printf NON (utilise malloc internement, donc dangereux dans un handler).

§5.8 — Récap

★ À retenir
  • kill(pid, sig) envoie un signal — pas tueur malgré le nom
  • kill(pid, 0) = ping non-destructif, idéal pour valider un PID
  • sigaction > signal (moderne, déterministe)
  • sa_mask + sigaddset = bloquer des signaux pendant le handler
  • pause() bloque jusqu à un signal — la boucle d attente du server
  • usleep(700) = délai côté client pour éviter pertes
  • write = sortie bas niveau, async-signal-safe (utilisable dans handler)
