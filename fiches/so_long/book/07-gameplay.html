CHAPITRE 07

Déplacements, events & compteur

le cœur du jeu : bouger, collecter, gagner, compter

§7.1 — Les touches à gérer

Le sujet impose W A S D pour bouger dans les 4 directions. ZQSD et les flèches sont autorisés en plus (note du sujet) — un bon réflexe sur clavier AZERTY/français.

ActionTouches
hautW / Z / flèche ↑
basS / flèche ↓
gaucheA / Q / flèche ←
droiteD / flèche →
quitterESC
★ Les keycodes
Les touches arrivent dans ton callback sous forme de keycode (un int). Ils diffèrent entre Linux et macOS (ex. ESC = 65307 sur Linux, 53 sur macOS). Définis-les en #define en haut de ton header pour un code lisible.

§7.2 — La logique d'un déplacement

Chaque touche directionnelle calcule une case cible (la case voisine). Ce qu'on y trouve décide de la suite :

// pseudo-code d'un move
cible = case voisine selon la direction

si cible == '1' (mur):
    ne rien faire   // le joueur ne bouge pas, pas de move compté
sinon:
    si cible == 'C': collectibles_restants--   // on ramasse
    si cible == 'E':
        si collectibles_restants == 0: VICTOIRE   // on sort
        sinon: on marche dessus mais on ne gagne pas encore
    déplacer le joueur sur la cible
    moves++
    afficher moves
    redessiner
★ Mur = pas de move
Le sujet dit : « the player should not be able to move into walls ». Si la cible est un mur, le joueur reste sur place et le compteur n'augmente pas. Incrémenter le compteur même quand on tape un mur est une erreur fréquente.

§7.3 — Le compteur de mouvements

★ La règle
« At every move, the current number of movements must be displayed in the shell. » À chaque déplacement valide, tu affiches le total dans le terminal (avec ton ft_printf ou write).

Deux styles d'affichage acceptés :

Moves: 1
Moves: 2
Moves: 3        // une ligne par move (simple, clair)

L'essentiel : le compteur est visible dans le shell à chaque pas. (L'afficher sur la fenêtre est un bonus, pas le mandatory — voir chap. 10.)

§7.4 — La condition de victoire

On gagne quand le joueur atteint E après avoir ramassé tous les collectibles. Tant qu'il reste un C, marcher sur E ne fait rien de spécial (on passe dessus).

joueur arrive sur E
↓
collectibles_restants == 0 ?
↓
oui → message de victoire + fermeture propre
★ À la victoire
Affiche un petit message (« You won in N moves! ») puis ferme la fenêtre et quitte proprement (même chemin de cleanup que ESC / croix — chap. 08). Pas de exit() sauvage qui leak.

§7.5 — Brancher les events

Deux callbacks au minimum :

  • clavier : mlx_hook(win, KeyPress, ...) ou mlx_key_hook → ta fonction handle_key
  • croix rouge : mlx_hook(win, DestroyNotify, ...) → ta fonction de fermeture
★ ESC et croix : même sortie
ESC (dans handle_key) et la croix (dans le hook DestroyNotify) doivent appeler la même fonction de cleanup. Sinon tu dupliques la logique de free et tu en oublies la moitié.

§7.6 — Récap

★ À retenir
  • WASD obligatoire ; ZQSD + flèches en bonus de confort
  • Définis les keycodes en #define
  • Mur → pas de déplacement, pas de move compté
  • Compteur affiché dans le shell à chaque move valide
  • Victoire = sortie E avec 0 collectible restant
  • ESC + croix → même fonction de fermeture propre
