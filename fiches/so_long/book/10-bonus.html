CHAPITRE 10

Le bonus

3 features qui rapportent — mais seulement si le mandatory est parfait

§10.1 — La règle d'or du bonus

★ Condition bloquante
« The bonus part will only be assessed if the mandatory part is PERFECT. » Si le mandatory n'est pas intégralement fait et sans le moindre dysfonctionnement, le bonus n'est même pas regardé. Conclusion : ne touche pas au bonus tant que ton mandatory n'est pas blindé (Norme, leaks, edge cases).

§10.2 — Les 3 bonus qui rapportent

BonusIdée
Ennemis qui patrouillentdes sprites se déplacent ; toucher un ennemi = game over
Animation de spritesle joueur (ou l'eau, etc.) s'anime sur plusieurs frames
Compteur à l'écranafficher le nombre de moves dans la fenêtre (pas dans le shell)
★ Fonctions en plus autorisées
Pour le bonus, tu peux utiliser d'autres fonctions si tu les justifies en defense. C'est là que gettimeofday() sert : cadencer les animations dans le temps.

§10.3 — Comment animer (concept)

MLX n'a pas de « moteur d'animation ». L'idée : utiliser mlx_loop_hook, qui appelle ta fonction en continu dans la boucle. Tu y mesures le temps écoulé (gettimeofday) et tu changes de frame toutes les ~150 ms.

// pseudo-code d'anim
loop_hook(game):
    maintenant = gettimeofday()
    si maintenant - dernier_frame > 150ms:
        frame = (frame + 1) % nb_frames
        redessiner le joueur avec game.player[frame]
        dernier_frame = maintenant
★ Ne pas saturer le CPU
Sans garde temporelle, loop_hook redessine des milliers de fois par seconde → 100% CPU. La condition « toutes les N ms » est indispensable.

§10.4 — Le compteur à l'écran

Utilise mlx_string_put(mlx, win, x, y, color, str) après chaque redraw. Comme le texte se dessine par-dessus la map, il faut le ré-afficher à chaque mouvement (sinon les anciens chiffres se superposent). Convertis l'entier en string avec ton ft_itoa de libft.

§10.5 — Les ennemis

Concept : un ou plusieurs ennemis bougent (souvent un aller-retour simple sur une ligne ou colonne). À chaque frame, on teste la collision joueur/ennemi : si même case → message de défaite + fermeture propre. Note que les ennemis ne sont pas dans les 5 chars de map standard ; à toi de définir comment tu les places (souvent un 6ᵉ char dans une map bonus, ou des positions codées).

★ Garde la barre basse
Le sujet dit lui-même : « don't spend too much time on this assignment ». Un aller-retour d'ennemi + une anim 2 frames + le compteur à l'écran suffisent à empocher les bonus. Pas besoin d'une IA.

§10.6 — Récap

★ À retenir
  • Bonus évalué seulement si mandatory parfait → finis le mandatory d'abord
  • 3 bonus : ennemis (game over au contact), anims, compteur à l'écran
  • Anims via mlx_loop_hook + garde temporelle (gettimeofday)
  • Compteur écran via mlx_string_put, ré-affiché à chaque move
  • Fichiers _bonus.c/h + règle bonus au Makefile
  • Reste simple — le sujet le dit explicitement
