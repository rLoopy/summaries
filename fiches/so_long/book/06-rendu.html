CHAPITRE 06

Le rendu : afficher la map

des textures .xpm à la fenêtre, case par case

§6.1 — La taille de la fenêtre

Chaque case de la map fait TILE × TILE pixels (souvent 32, 48 ou 64). La fenêtre se dimensionne donc à partir de la map :

largeur_fenetre = map.cols * TILE
hauteur_fenetre = map.rows * TILE
★ Pourquoi calculer ?
La fenêtre doit coller exactement à la map, peu importe sa taille. Une fenêtre fixe (ex. 1280×720) couperait les grandes maps ou laisserait du vide sur les petites. On la calcule donc dynamiquement.

§6.2 — Charger les textures une fois

Au lancement (après la validation), tu charges chaque .xpm en image MLX une seule fois, et tu gardes les pointeurs dans ta struct :

// 5 textures de base (mandatory)
img.wall  = mlx_xpm_file_to_image(mlx, "textures/wall.xpm", &w, &h);
img.floor = mlx_xpm_file_to_image(mlx, "textures/floor.xpm", &w, &h);
img.player= mlx_xpm_file_to_image(mlx, "textures/player.xpm", &w, &h);
img.coll  = mlx_xpm_file_to_image(mlx, "textures/collect.xpm", &w, &h);
img.exit  = mlx_xpm_file_to_image(mlx, "textures/exit.xpm", &w, &h);
★ Toujours tester le retour
mlx_xpm_file_to_image renvoie NULL si le fichier manque ou est mal formé. Si tu ne testes pas, tu colles une image NULL → crash. Vérifie chaque chargement et quitte proprement sinon. C'est pour ça que textures/ doit être dans le repo.

§6.3 — La boucle de dessin

Pour afficher la map, on parcourt la grille et, pour chaque case, on colle la bonne image à la position pixel correspondante :

// pseudo-code
pour y de 0 à rows-1:
    pour x de 0 à cols-1:
        // le sol d'abord, partout (sauf murs)
        choisir l'image selon grid[y][x]:
            '1' → wall
            '0' → floor
            'C' → collectible
            'E' → exit
            'P' → player
        mlx_put_image_to_window(mlx, win, image, x*TILE, y*TILE)
★ Sol sous les objets
Le joueur, les collectibles et la sortie se posent sur du sol. Une approche propre : dessiner le floor partout d'abord, puis re-coller le joueur/collectible/exit par-dessus aux bonnes cases. Avec des textures sans transparence, tu peux aussi mapper directement chaque char à une image pleine — au choix.

§6.4 — Coordonnées : (x, y) vs (col, row)

★ Le piège d'inversion
Dans la grille, on indexe grid[y][x] : y = ligne (row), x = colonne (col). Mais mlx_put_image_to_window attend (x_pixel, y_pixel) dans l'ordre x puis y. Donc on colle à (x*TILE, y*TILE). Inverser les deux est l'erreur classique : la map s'affiche en miroir/transposée.

§6.5 — Quand redessiner ?

so_long n'est pas en temps réel (le sujet le dit). On ne redessine que quand le joueur bouge. Le flux :

touche pressée (callback clavier)
↓
on met à jour la position dans la grille
↓
on redessine (au moins la zone qui change)

Le plus simple pour commencer : tout redessiner à chaque move. C'est suffisant pour le mandatory. Tu peux optimiser plus tard (ne redessiner que l'ancienne et la nouvelle case du joueur).

§6.6 — Récap

★ À retenir
  • Fenêtre dimensionnée : cols*TILE × rows*TILE
  • Charger chaque .xpm une fois, garder les pointeurs
  • Tester le retour de mlx_xpm_file_to_image (NULL = erreur)
  • Double boucle : coller la bonne image à (x*TILE, y*TILE)
  • Ne pas inverser x et y dans put_image_to_window
  • Redessiner à chaque déplacement (pas de temps réel)
