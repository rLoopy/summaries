01La mémoire, c'est quoi ?

Quand ton programme tourne, il a une grosse zone de travail : la RAM. Imagine une rangée géante de casiers numérotés, chacun peut contenir un octet (8 bits, un petit nombre entre 0 et 255).

RAM (vue simplifiée)
0x100?
0x101?
0x102?
0x103?
...
0x7FA0?

Chaque casier a une adresse unique (un numéro en hexadécimal, genre 0x100). Le numéro, c'est où il est. Le contenu, c'est quoi est dedans.

★ À retenir
adresse = l'emplacement (le numéro du casier). valeur = ce qu'il y a dedans. Deux concepts différents qu'on confond souvent.

02Variables & adresses

Quand t'écris int x = 42;, le compilateur dit au système : "trouve-moi 4 casiers libres, appelle-les x, et écris 42 dedans".

déclaration : int x = 42;
0x100 42
← c'est la variable x

Tu as maintenant deux infos sur x :

  • ▸ sa valeur : x (écrit tout seul) = 42
  • ▸ son adresse : &x (avec le &) = 0x100

Le & veut dire "donne-moi l'adresse de". Tu le connais de scanf("%d", &x) en débutant.

Check : si int y = 7; est stockée à 0x200...
...que valent y et &y ?
y = 7 (la valeur)  ·  &y = 0x200 (l'adresse où vit la variable)

03Les pointeurs (& et *)

Un pointeur, c'est une variable qui, au lieu de contenir un nombre, contient une adresse.

int x = 42;
int *p = &x;   // p stocke l'adresse de x
état mémoire
0x100 42
x    
0x500 0x100
p (contient l'adresse de x)

Le type int * veut dire "pointeur vers un int". L'étoile dit "c'est une adresse, pas un int direct".

Les deux opérations clés

ExpressionCe qu'elle faitRésultat
&xprend l'adresse de x0x100
*pva voir ce qu'il y a à l'adresse dans p42
pla valeur de p lui-même0x100
★ La dualité du *
Le * a deux rôles qui n'ont rien à voir :
  • ▸ Dans un type : int *p → "p est un pointeur vers int"
  • ▸ Dans une expression : *p → "va chercher la valeur pointée par p"
C'est le même symbole mais pas le même sens. C'est nul, mais c'est C.

Écrire via un pointeur

Si tu écris *p = 99, tu dis "va à l'adresse dans p, et écris 99 là-bas". Résultat : x vaut maintenant 99 (car p pointait sur x).

Check : après int x = 10; int *p = &x; *p = 50;
Combien vaut x ?
x vaut 50. *p = 50 a modifié la case mémoire où vit x.

04Stack vs Heap

La mémoire de ton programme est divisée en deux zones principales :

StackHeap
Variables locales, paramètres, appels de fonctions.
Création : auto, à l'entrée d'une fonction.
Destruction : auto, à la sortie. 		Mémoire allouée à la demande via malloc.
Création : toi, explicitement.
Destruction : toi, avec free. 
void demo(void)
{
  int x = 42;          // x vit sur la STACK
  int *p = malloc(sizeof(int)); // *p vit sur le HEAP
  *p = 99;
  // à la fin de la fonction :
  //   x disparaît automatiquement (stack unwind)
  //   *p reste en vie ! (c'est sur le heap)
}
⚠ Le piège classique
Si tu retournes l'adresse d'une variable locale, tu retournes un pointeur vers de la mémoire morte. 
int *fonction_pourrie(void)
{
  int x = 42;
  return (&x);  // ← x meurt ici, retour d'un pointeur vers du vide
}
Pour retourner quelque chose qui survit à la fonction, il faut le mettre sur le heap via malloc.

C'est exactement ce que fait stack_new : elle retourne un pointeur vers une boîte qui survit grâce à malloc.

05malloc & free

malloc(n) réserve n octets de mémoire sur le heap et te donne l'adresse de cette zone. Si la RAM est pleine, il retourne NULL.

int *p = malloc(sizeof(int));  // réserve 4 octets pour un int
if (!p)
  return ;                // malloc a raté, plus de RAM
*p = 42;                    // écris 42 dans la zone allouée
// ... plus tard ...
free(p);                   // libère la zone, sinon memory leak
💡 sizeof(*p) vs sizeof(int)
malloc(sizeof(*p)) est mieux que malloc(sizeof(int)). Pourquoi ? Parce que si un jour tu changes le type de p, t'as rien à toucher — sizeof(*p) s'adapte tout seul. C'est pour ça que dans stack_new on écrit malloc(sizeof(*node)).

Règle d'or : chaque malloc doit avoir son free. Sinon, memory leak (la RAM se remplit jusqu'au crash).

06Les structs

Une struct, c'est une manière de grouper plusieurs variables en un seul "paquet".

typedef struct  s_stack
{
  int             val;
  struct s_stack  *next;
} t_stack;

Lecture de cette déclaration :

  • ▸ On définit un type appelé t_stack
  • ▸ Une variable de ce type contient 2 champs : un int val et un pointeur next
  • ▸ Le next pointe vers un autre t_stack (récursif dans le type — c'est ce qui permet la chaîne)
une boîte t_stack en mémoire
0x7FA0
val: 3
next: 0x7FB0
─►
0x7FB0
val: 1
next: NULL

Chaque boîte fait environ 16 octets (4 pour l'int + 8 pour le pointeur + padding). Et next contient l'adresse de la prochaine boîte.

07Accéder aux champs : . et ->

Tu as deux opérateurs pour accéder aux champs d'une struct :

SyntaxeQuand l'utiliser
s.valquand s est une struct directe (pas un pointeur)
p->valquand p est un pointeur vers une struct
t_stack box;              // box est une struct directe
box.val = 3;                // point pour la struct directe

t_stack *p = &box;         // p est un pointeur vers une struct
p->val = 3;                // flèche pour le pointeur

// les deux sont équivalents :
p->val        // raccourci
(*p).val      // version longue : d'abord déréférence, puis point
★ Mnémo
La flèche -> fait deux choses d'un coup : déréférence (va voir la struct pointée) + accède au champ. En C, on n'utilise quasiment que -> avec les structs via pointeur (et en push_swap, c'est tout le temps des pointeurs).
Check : si t_stack *node est un node avec val=5, next=NULL
Comment on lit sa valeur ? Comment on met son next à une autre adresse ?
Lire : node->val (donne 5).
Écrire next : node->next = autreNode;

08Linked list : la chaîne

Une linked list, c'est plusieurs boîtes t_stack attachées les unes aux autres via leur champ next.

la pile [3, 1, 4, 2] — emplacements arbitraires en mémoire
0x7FA0val=3
next=0x7FB0
→
0x7FB0val=1
next=0x7FC0
→
0x7FC0val=4
next=0x7FD0
→
0x7FD0val=2
next=NULL

Observations importantes :

  • ▸ Les boîtes sont dispersées dans la RAM. 0x7FA0, 0x7FB0, ... c'est pas contigu en général, c'est juste par chance que j'ai aligné ici.
  • ▸ Le seul lien entre elles, c'est le next. Perdre un next, c'est perdre tout ce qui suit.
  • ▸ La dernière boîte a next = NULL. C'est le marqueur "fin de chaîne".

09Le head et NULL

Pour accéder à la chaîne depuis l'extérieur, tu as besoin d'un seul point d'entrée : le head. C'est une variable de type t_stack * qui contient l'adresse de la première boîte.

le head pointe vers la 1ère boîte
0x100 0x7FA0
head (sur la stack)

↓ pointe vers

0x7FA0val=3
next=0x7FB0
→
0x7FB0val=1
next=NULL

Si head == NULL, ça veut dire la pile est vide. Pas de première boîte, pas de chaîne.

⚠ Perdre le head = catastrophe
Si tu écrases head sans l'avoir sauvegardé ailleurs, tu perds l'accès à toutes les boîtes en dessous. Elles sont toujours en RAM, mais tu n'as plus leur adresse. Memory leak permanent.

10Parcourir avec un curseur

Pour se balader dans une linked list, on utilise un curseur : un pointeur qu'on déplace de boîte en boîte.

t_stack *cur = head;   // le curseur part du head
while (cur)            // tant qu'on n'est pas sur NULL
{
  printf("%d\n", cur->val);  // fais un truc avec la boîte
  cur = cur->next;     // avance d'une boîte
}

Déroulement visuel sur la liste [3, 1, 4] :

étape 1 : cur pointe sur la 1ère boîte
0x7FA0val=3
→
0x7FB0val=1
→
0x7FC0val=4
→ NULL
cur = 0x7FA0
étape 2 : cur = cur->next
0x7FA0val=3
→
0x7FB0val=1
→
0x7FC0val=4
→ NULL
cur = 0x7FB0
étape 3 : cur = cur->next
0x7FA0val=3
→
0x7FB0val=1
→
0x7FC0val=4
→ NULL
cur = 0x7FC0
étape 4 : cur = cur->next = NULL, la boucle s'arrête
cur = NULL ← la condition while (cur) devient fausse

Variante : s'arrêter sur la dernière, pas après

Parfois tu veux t'arrêter sur la dernière boîte (pas NULL). C'est le cas si tu veux attacher un nouveau node à la fin.

t_stack *cur = head;
while (cur->next)       // tant que le suivant existe
  cur = cur->next;       // avance
// ici : cur est sur la DERNIÈRE boîte (cur->next == NULL)
★ Différence cruciale
while (cur) → s'arrête quand cur est NULL (tu as dépassé la fin).
while (cur->next) → s'arrête quand le suivant est NULL (tu es pile sur la fin).
Pour stack_add_bottom, tu veux la deuxième forme.

11Pourquoi t_stack ** ?

C'est LA notion qui coince le plus. Attaque bien cette partie.

Le problème : C passe par valeur

En C, quand tu passes un argument à une fonction, la fonction reçoit une copie. Si la fonction modifie cette copie, l'original ne bouge pas.

void essayer_de_modifier(int x)
{
  x = 99;   // modifie la COPIE locale
}

int main(void)
{
  int a = 10;
  essayer_de_modifier(a);
  printf("%d\n", a);   // affiche 10, pas 99 !
}

La solution : passer un pointeur

Si on veut modifier une variable depuis une fonction, on passe l'adresse de cette variable :

void modifier_pour_de_vrai(int *x)
{
  *x = 99;   // va à l'adresse reçue, écris 99 là-bas
}

int main(void)
{
  int a = 10;
  modifier_pour_de_vrai(&a);   // passe l'adresse de a
  printf("%d\n", a);    // affiche 99
}

Appliqué à notre pile

Dans build_stack, on a une variable t_stack *stack (un pointeur vers un node, qui est le head). On veut qu'stack_add_bottom puisse modifier ce head (cas de la pile vide).

Le stack de build_stack est déjà un pointeur (t_stack *). Pour le modifier depuis une autre fonction, il nous faut un pointeur vers ce pointeur → t_stack **.

appel : stack_add_bottom(&stack, 3)
dans build_stack :
0x100 stack = NULL
dans stack_add_bottom :
0x200 stack (param) = 0x100
← contient l'adresse de la variable d'en haut

Lecture des expressions

Dans stack_add_bottom :

ExpressionTypeCe que c'estValeur (ici)
stackt_stack **adresse de la variable d'en haut0x100
*stackt_stack *la variable d'en haut elle-même (le head)NULL
**stackt_stackla struct pointée par le head (crash si head = NULL !)—
★ La règle d'or
Pour modifier le head de celui qui nous a appelés, il faut écrire *stack = .... Pas stack = ... (qui ne ferait que changer notre copie locale du pointeur).
Check : si on veut faire pointer le head vers une nouvelle boîte new
On écrit quoi ?
*stack = new;
→ "va à l'adresse stockée dans stack (c'est-à-dire l'endroit où vit la variable head de l'appelant), et écris new".

12Décrypter stack_add_bottom

Maintenant tu as tout. Regardons le squelette ligne par ligne.

void stack_add_bottom(t_stack **stack, int val)
{
  t_stack *new;
  t_stack *cur;

  /* TROU B1 : new = stack_new(val). Si NULL, return. */
  /* TROU B2 : si *stack est NULL, c'est le 1er : *stack = new, return. */
  /* TROU B3 : sinon, parcours jusqu'au dernier (cur->next == NULL). */
  /* TROU B4 : attache le new au dernier (cur->next = new). */
}

Signature : qu'est-ce qu'on reçoit ?

  • ▸ t_stack **stack : l'adresse de la variable head de l'appelant. Sert à modifier le head si besoin.
  • ▸ int val : la valeur à ajouter. Un simple int, pas de pointeur.
  • ▸ Retour void : on ne retourne rien, la modification se fait via *stack.

Variables locales

  • ▸ new : pointeur vers la boîte fraîchement fabriquée
  • ▸ cur : pointeur curseur pour parcourir la chaîne

Logique des 4 trous

💡 B1 — fabriquer la boîte
Quoi faire : créer la boîte en appelant stack_new(val), stocker le résultat dans new.
Cas d'erreur : si stack_new retourne NULL (malloc a raté), il faut sortir de la fonction avec return (la fonction est void, donc juste return ;).
💡 B2 — pile vide
Test : est-ce que la pile est vide ? → *stack == NULL (ou !*stack).
Si oui : le head doit devenir new. Tu écris *stack = new; puis return ;.
Pourquoi *stack et pas stack ? Parce que stack c'est l'adresse de la variable d'en haut, et *stack c'est la variable elle-même. On veut modifier la variable, donc *stack = ....
💡 B3 — parcourir jusqu'au dernier
Initialiser : cur = *stack (cur part du head).
Boucle : tant que cur->next n'est pas NULL, cur = cur->next.
Après la boucle : cur est sur la dernière boîte (la seule dont le next vaut NULL).
Attention à la condition : while (cur) va trop loin (cur devient NULL, crash après). while (cur->next) s'arrête pile sur la dernière.
💡 B4 — attacher
Une ligne : cur->next = new;. On remplace le NULL de la dernière boîte par l'adresse de la nouvelle boîte. La chaîne est allongée d'un cran.

Diagramme des 2 chemins

                  │  B1 : new = stack_new(val)      │
                  │       si NULL → return ;        │
                  └──────────────┬──────────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 │                               │
           *stack == NULL                  *stack != NULL
           (pile vide)                    (pile a des éléments)
                 │                               │
                 ▼                               ▼
         ┌──────────────┐               ┌─────────────────┐
         │     B2       │               │      B3         │
         │ *stack = new │               │ cur = *stack    │

         └──────────────┘               │   cur = cur->next│
                                        └────────┬────────┘

                                        │ cur->next = new  │
                                        └──────────────────┘

13Tu es prêt à coder

Voilà la check-list mentale quand tu écris stack_add_bottom :

  1. Crée la boîte avec stack_new, gère le cas où ça rate.
  2. Teste si la pile est vide (*stack == NULL). Si oui, fait de new le nouveau head et sors.
  3. Sinon, initialise un curseur à partir du head et avance jusqu'à la dernière boîte.
  4. Attache la nouvelle boîte au next de la dernière.
★ Test mental avant de taper
Déroule sur papier avec ces 3 cas :
1. *stack = NULL, tu ajoutes 5 → résultat attendu ?
2. *stack = [7|NULL], tu ajoutes 5 → résultat attendu ?
3. *stack = [7|●] → [3|NULL], tu ajoutes 5 → résultat attendu ?
Si tu peux dire à voix haute ce qui se passe dans les 3, tu peux coder.
Check final
Quelle ligne est fausse ? stack = new ou *stack = new ?
stack = new est faux (ne modifie que la copie locale du paramètre).
*stack = new est correct (modifie la vraie variable de l'appelant).
Quelle boucle est correcte pour s'arrêter sur le dernier node ?
while (cur->next) cur = cur->next;
(while (cur) irait trop loin, jusqu'à NULL)
Pourquoi le return après B2 ?
Pour ne pas entrer dans la logique B3/B4. Si la pile était vide, on a fait *stack = new et c'est terminé — il n'y a pas de "fin de chaîne" à parcourir, la chaîne contient une seule boîte.

Maintenant retourne dans stack.c et remplis les TROUs B1 → B4. Tu as toutes les clés.
