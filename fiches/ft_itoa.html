ft_itoa
int → string ↓

Transformer un int en string allouée avec malloc. Seule fonction autorisée : malloc. Un piège overflow sournois au milieu.

ce coup-ci, pas de write.
tu dois malloc une string et renvoyer son adresse.
malloc only char * ~35 lignes 20 min ☕

voilà ce que la fonction fait.

Tu passes un int, elle te retourne un char * qui pointe sur une string fraîchement malloc'ée.

exemples
ft_itoa(42) → "42"
ft_itoa(0) → "0"
ft_itoa(-123) → "-123"
ft_itoa(2147483647) → "2147483647" // INT_MAX
ft_itoa(-2147483648)→ "-2147483648" // INT_MIN, le piège !
null-terminée (finit par '\0'), de longueur variable selon le nombre.

3 pièges à connaître avant.

Ce qui rend l'exo plus mathy que rostring :

on connaît pas la longueur au départ

42 fait 2 chars, 1000000 en fait 7, -9 en fait 2. Faut compter les digits avant de malloc.

gérer le signe

Si le nombre est négatif, faut rajouter '-' au début et bosser avec sa valeur absolue. MAIS voir piège #3...

le piège INT_MIN

Si nbr = -2147483648, faire -nbr overflow parce que +2147483648 tient pas dans un int signé (max = 2147483647). Solution : passer par un long.

focus : le piège INT_MIN.

Un int signé sur 32 bits peut contenir : −2 147 483 648 à +2 147 483 647. Remarque que les négatifs descendent un cran plus bas que les positifs ne montent.

Le bug classique

Si tu fais :

int nbr = -2147483648;
int n = -nbr;       // ⚠ overflow !
// n contient... -2147483648 (pas ce qu'on voulait)

Pourquoi ? Parce que +2 147 483 648 n'existe pas dans le monde des int. Quand tu dépasses INT_MAX, tu wrap autour et tu retombes sur INT_MIN.

✦ le fix ✦

Copier dans un long (64 bits)

Un long va de ±9.2 × 10¹⁸. Le +2147483648 y rentre les doigts dans le nez.

long n = nbr; // copie auto int → long, pas de problème
if (n < 0)
    n = -n; // ok, long peut contenir +2147483648

convertir un digit en caractère.

Un int 7 n'est PAS la même chose que le caractère '7'. Un char '0' vaut 48 en ASCII, '1' vaut 49, etc.

Pour convertir un digit (0-9) en son caractère : ajouter '0'.

0+ '0' ='0'
1+ '0' ='1'
2+ '0' ='2'
5+ '0' ='5'
7+ '0' ='7'
9+ '0' ='9'
pour extraire le dernier digit : n % 10. pour le virer : n / 10.

la règle d'or ★

pense à la string À L'ENVERS.

Pour extraire les digits un par un, t'es obligé de partir par la fin. n % 10 donne le dernier, n / 10 l'enlève. Remplis result de droite à gauche, ajoute le - en dernier si besoin, et laisse toujours '\0' à la fin.
