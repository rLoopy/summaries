CHAPITRE 09

Le Makefile

compiler ton code + libft + MiniLibX, et linker tout ça

§9.1 — Ce que le sujet exige

★ Contraintes Makefile
  • Règles obligatoires : $(NAME), all, clean, fclean, re
  • Compilation avec -Wall -Wextra -Werror
  • Ne doit pas relink inutilement (pas de recompil si rien n'a changé)
  • Compile ta libft via son propre Makefile (dossier libft/)
  • Une règle bonus si tu fais le bonus (fichiers _bonus.c/h)

§9.2 — Le défi : 3 choses à compiler

so_long n'est pas qu'un seul code : il faut assembler trois briques avant de produire le binaire.

libft → libft.a (via son Makefile)
↓
MiniLibX → libmlx.a (via son Makefile)
↓
tes .c → .o
↓
link les .o + les .a + libs système → so_long

§9.3 — Le linking, là où ça coince

La MiniLibX dépend de bibliothèques système. Sur Linux, l'ordre et les flags comptent :

# flags de link typiques (Linux, minilibx-linux)
MLX_FLAGS = -L./minilibx-linux -lmlx -lXext -lX11 -lm
★ Erreurs de link fréquentes
  • undefined reference to XOpenDisplay → il manque -lX11
  • undefined reference to XShm... → il manque -lXext
  • référence math non résolue → il manque -lm
  • libft non trouvée → vérifie -L./libft -lft et que libft.a existe
Sur macOS les flags diffèrent (-framework OpenGL -framework AppKit). Adapte selon ta machine de rendu.

§9.4 — La structure d'un Makefile propre

Sans te donner le fichier complet, voici les blocs à assembler toi-même :

# 1. Variables : NAME, CC, CFLAGS, dossiers, SRC, OBJ
# 2. Règle all : dépend de $(NAME)
# 3. Règle $(NAME) :
#      - make -C libft        (compile la libft)
#      - make -C minilibx-linux (compile la mlx)
#      - $(CC) $(OBJ) -L libs... -o $(NAME)
# 4. Règle %.o : %.c   (compilation incrémentale → pas de relink)
# 5. clean   : rm les .o (et ceux des libs si tu veux)
# 6. fclean  : clean + rm $(NAME) + les .a
# 7. re      : fclean puis all
# 8. .PHONY  : all clean fclean re bonus
★ Le secret du "pas de relink"
La règle de motif %.o : %.c ne recompile qu'un .c modifié. La clé : la cible $(NAME) dépend des $(OBJ), qui dépendent de leurs .c. Si rien ne change, make dit « Nothing to be done » — c'est exactement ce que l'évaluateur vérifie en lançant make deux fois de suite.

§9.5 — La règle bonus

Si tu fais le bonus, le sujet impose une règle bonus séparée et des fichiers *_bonus.c / *_bonus.h. Mandatory et bonus sont évalués séparément — souvent on duplique l'arbo en _bonus. Attention : ne pas mélanger, sinon l'évaluation mandatory voit du code bonus.

§9.6 — Récap

★ À retenir
  • Règles : $(NAME) all clean fclean re (+ bonus)
  • Compile libft et mlx via leurs propres Makefiles (make -C)
  • Link Linux : -lmlx -lXext -lX11 -lm
  • Règle %.o : %.c → compilation incrémentale, pas de relink
  • .PHONY pour les cibles qui ne sont pas des fichiers
  • Bonus = règle + fichiers _bonus séparés
