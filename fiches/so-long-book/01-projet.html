CHAPITRE 01

Le sujet et le projet

ce qu'on doit livrer, les contraintes, les fonctions autorisées

§1.1 — Le but du projet

so_long est un projet 42 du cercle graphique. Le sujet le décrit comme « un petit jeu 2D où un dauphin s'échappe de la Terre après avoir mangé des poissons ». Concrètement, peu importe le thème : tu dois coder un jeu où un personnage parcourt une carte, ramasse tous les objets à collecter, puis sort par la sortie.

★ En une phrase
Le joueur doit collecter tous les collectibles de la map, puis s'échapper par la sortie en empruntant le chemin le plus court possible. À chaque déplacement, le nombre de mouvements s'affiche dans le terminal.

Le projet t'apprend à utiliser une bibliothèque graphique (MiniLibX) : ouvrir une fenêtre, gérer des images/textures, et réagir aux événements clavier et souris. C'est ta première rencontre avec le rendu graphique au cursus.

Tu dois rendre les dossiers maps/ (tes cartes .ber) et textures/ (tes images .xpm) en plus du code. Sans textures, ton jeu ne tourne pas chez l'évaluateur.

§1.3 — Les fonctions autorisées

Le sujet liste précisément ce que tu peux appeler. Rien d'autre :

open, close, read, write   // I/O fichier (lire la map)
malloc, free             // alloc dynamique (grille, structs)
perror, strerror         // messages d'erreur système
exit                     // quitter
// + toutes les fonctions de la lib math (-lm, man 3 math)
// + toutes les fonctions de la MiniLibX
gettimeofday             // utile pour le timing des anims (bonus)
ft_printf                // ou ton équivalent codé
★ Piège classique
Pas de printf de la libc dans le code de prod : utilise ton ft_printf (ou write) pour afficher le compteur de moves. Et pas de get_next_line « magique » non autorisé… en réalité tu peux recoder ta lecture avec read + ta libft, mais GNL n'est pas dans la liste officielle — utilise-le seulement s'il vient de ta libft que tu copies dans le projet.

§1.4 — Les contraintes communes (cercle commun)

Comme tous les projets du tronc commun, so_long est soumis aux règles générales :

★ Règles non négociables
  • Code en C, conforme à la Norme (les fichiers bonus sont aussi normés → 0 si erreur)
  • Aucun crash : pas de segfault, bus error, double free → sinon projet non-fonctionnel = 0
  • Zéro leak : toute mémoire malloc doit être libérée. Les leaks ne sont pas tolérés
  • Makefile compile avec -Wall -Wextra -Werror via cc, et ne relink pas inutilement
  • Règles Makefile : $(NAME), all, clean, fclean, re (+ bonus si bonus)
  • Si tu utilises ta libft : copie ses sources + son Makefile dans un dossier libft/, et ton Makefile la compile via son propre Makefile
  • Le travail n'est évalué que dans le dépôt Git rendu

§1.5 — Une architecture type

so_long est plus gros que minitalk mais plus simple que push_swap niveau algo. Une structure claire t'évite de te noyer :

so_long/
├── includes/
│   └── so_long.h        // structs, prototypes, defines
├── src/
│   ├── main.c           // entrée, init, lancement
│   ├── parse_map.c      // lecture + stockage de la grille
│   ├── check_map.c      // validation (rect, murs, P/E/C)
│   ├── flood_fill.c     // vérif chemin valide
│   ├── render.c         // charge textures + dessine
│   ├── moves.c          // events clavier + déplacements
│   └── cleanup.c        // free de tout + exit propre
├── textures/            // .xpm (mur, sol, joueur, collectible, exit)
├── maps/                // .ber d'exemple
├── libft/               // ta libft + son Makefile
├── Makefile
└── README.md
★ Conseil
Une seule grosse struct de jeu (souvent appelée t_game) qui contient le pointeur mlx, la fenêtre, la grille de la map, les dimensions, les compteurs (collectibles restants, moves) et les images. Tu la passes partout par pointeur. Ça évite les variables globales (interdites de fait) et simplifie le free final.

§1.6 — Récap

★ À retenir de ce chapitre
  • Jeu 2D : ramasser tous les C, puis sortir par E
  • Compteur de moves affiché à chaque déplacement
  • Argument unique : une map .ber
  • Rendre aussi les dossiers maps/ et textures/
  • Norme, zéro leak, zéro crash, Makefile sans relink
  • Une struct de jeu centrale passée par pointeur
