CHAPITRE 04

Parsing & validation de la map

lire le fichier, stocker la grille, tout vérifier avant d'afficher

§4.1 — L'ordre des opérations

La règle d'or : tout valider avant d'ouvrir la moindre fenêtre. Si la map est invalide, on affiche l'erreur et on quitte — on n'a même pas appelé mlx_init.

1. vérifier l'argument (1 seul, finit par .ber)
↓
2. lire le fichier → grille en mémoire
↓
3. valider (rect, murs, chars, compteurs)
↓
4. flood fill (chemin valide — chap. 05)
↓
5. seulement maintenant : MLX + rendu

§4.2 — Stocker la grille

La représentation classique : un char **map — un tableau de strings, une par ligne. C'est exactement ce que renvoie un get_next_line en boucle, ou une lecture read + un split sur \n.

// idée de struct (à toi de l'écrire)
typedef struct s_map
{
    char **grid;     // les lignes
    int  rows;       // hauteur
    int  cols;       // largeur
    int  collectibles;
    int  players;
    int  exits;
}   t_map;
★ Astuce lecture
Lis toute la map d'abord, puis valide. Lire ligne par ligne en validant à la volée complique le free en cas d'erreur au milieu. Plus simple : tout charger, valider, et si invalide → free + erreur.

§4.3 — Les checks, un par un

Rectangulaire

Compare la longueur de chaque ligne à celle de la première. Une seule différente → erreur. Attention au \n final de la dernière ligne et à une éventuelle ligne vide à la fin du fichier.

Entourée de murs

La première et la dernière ligne ne doivent contenir que des 1. Pour les lignes du milieu, le premier et le dernier caractère doivent être 1.

ligne 0 → 11111111 (tout 1) lignes 1..n-1 → 1......1 (bords = 1) ligne n → 11111111 (tout 1)

Caractères & compteurs

Une seule boucle sur toute la grille suffit : pour chaque case, soit c'est un char autorisé (on incrémente le bon compteur), soit erreur immédiate.

// pseudo-code — pas la solution finale
pour chaque (y, x) de la grille:
    c = grid[y][x]
    si c == 'P': players++
    sinon si c == 'E': exits++
    sinon si c == 'C': collectibles++
    sinon si c != '0' et c != '1': ERREUR (char interdit)

à la fin: exiger players==1 ET exits==1 ET collectibles>=1

§4.4 — Les pièges du parsing

★ Ce qui fait planter
  • Ligne vide au milieu ou à la fin du fichier → souvent prise pour une ligne de largeur 0, casse le check rectangulaire
  • Espaces invisibles en fin de ligne → char interdit, mais difficile à voir à l'œil
  • Map d'une seule ligne ou vide → ton code doit gérer sans segfault
  • Dernière ligne sans \n → elle n'a pas la même « forme » que les autres, gère les deux cas
  • Fichier inexistant / pas les droits → open renvoie -1, gère-le proprement
★ Conseil de test
Prépare un dossier maps/bad/ rempli de cas tordus (pas fermée, 2 E, char interdit, vide, 1 ligne…). En defense, tu montres que chacun sort proprement avec un message clair. Ça impressionne et c'est exactement ce que l'évaluateur teste.

§4.5 — Récap

★ À retenir
  • Valider tout avant d'ouvrir la fenêtre
  • Grille = char ** (une string par ligne)
  • Checks : rectangulaire, murs, chars autorisés, compteurs P/E/C
  • Une boucle unique compte P/E/C et détecte les chars interdits
  • Pièges : lignes vides, espaces, \n final, fichier introuvable
  • Garde un dossier de maps cassées pour la defense
