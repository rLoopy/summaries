CHAPITRE 02

MiniLibX : la lib graphique

window, image, hooks — les briques de base à comprendre

§2.1 — C'est quoi MiniLibX ?

La MiniLibX (MLX) est une mini-bibliothèque graphique développée en interne à 42. Elle te donne le strict nécessaire : ouvrir une fenêtre, dessiner des pixels/images dedans, et écouter le clavier et la souris. Elle s'appuie sur X11 (Linux) ou OpenGL (macOS).

★ Deux versions
Sur les machines de l'école elle est préinstallée. Sinon tu clones les sources et tu compiles. Sur Linux on utilise généralement minilibx-linux (la version maintenue), qui se link avec -lXext -lX11 -lm.

§2.2 — Le cycle de vie d'un programme MLX

mlx_init()
connexion au serveur graphique
↓
mlx_new_window()
crée la fenêtre
↓
charger images + dessiner
textures → image → fenêtre
↓
mlx_hook / key_hook
brancher clavier + croix
↓
mlx_loop()
boucle infinie d'événements

mlx_loop() ne rend jamais la main : c'est lui qui appelle tes fonctions de callback quand un événement arrive (touche pressée, fenêtre fermée…). Tout ce qui doit réagir au joueur vit dans ces callbacks.

§2.3 — Les fonctions clés

FonctionRôle
mlx_init()initialise la connexion, retourne le pointeur mlx
mlx_new_window(mlx, w, h, title)ouvre une fenêtre de taille w×h
mlx_xpm_file_to_image(...)charge un fichier .xpm en image MLX

mlx_string_put(...)écrit du texte (utile bonus : compteur à l'écran)

§2.4 — Image vs pixel : pourquoi les images sont obligatoires

Le sujet exige explicitement : « The use of the images of the MiniLibX is mandatory ». Pourquoi ?

✗ pixel par pixel

mlx_pixel_put dessine directement dans la fenêtre, un pixel à la fois. C'est très lent et ça scintille. Interdit comme méthode principale ici.

✓ images / textures

On charge une image une fois (depuis un .xpm), puis on la colle en bloc avec mlx_put_image_to_window. Rapide, propre, et exigé par le sujet.
★ Le concept .xpm
Un .xpm est un format d'image en texte (un tableau de couleurs) que MLX sait lire nativement via mlx_xpm_file_to_image. Tu prépares une texture par type de case : mur, sol, joueur, collectible, sortie. Toutes à la même taille (ex. 64×64).

§2.5 — Les events à gérer

Le sujet impose un comportement précis sur deux événements :

  • Touche ESC → ferme la fenêtre et quitte proprement
  • Clic sur la croix rouge de la fenêtre → ferme et quitte proprement
★ La croix rouge piège tout le monde
La croix n'est pas une touche : c'est l'événement DestroyNotify (code 17) qu'on branche avec mlx_hook. Beaucoup d'étudiants gèrent ESC mais oublient la croix → le programme leak ou ne quitte pas proprement. Les deux doivent appeler ta même fonction de fermeture (chap. 08).

§2.6 — Récap

★ À retenir
  • Cycle : init → new_window → images → hooks → mlx_loop
  • mlx_loop est bloquant : toute la logique vit dans les callbacks
  • Images obligatoires (pas pixel_put en méthode principale)
  • Une texture .xpm par type de case, même taille
  • ESC et croix rouge → fermeture propre via la même fonction
