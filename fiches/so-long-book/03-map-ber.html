CHAPITRE 03

Le format de map .ber

les 5 caractères et les règles de validité

§3.1 — Les 5 caractères autorisés

Une map est un fichier texte avec l'extension .ber. Elle ne peut contenir que 5 caractères (plus les retours à la ligne) :

CharSignification
0espace vide (le sol, on peut marcher dessus)
1un mur (infranchissable)
Cun collectible (à ramasser)
Ela sortie (map exit)
Pla position de départ du joueur (player)
★ Aucun autre caractère
Tout caractère qui n'est pas dans cette liste (espace, lettre, chiffre autre…) rend la map invalide. Ton parsing doit refuser ./so_long maps/azerty.ber si la grille contient un 9 ou un X.

§3.2 — Une map valide minimale

1111111111111 1001000000C11 1000011110001 1P0011E0000 1 ← (exemple inspiré du sujet) 1111111111111

Lecture : un rectangle entièrement entouré de murs 1, avec un P (départ), un E (sortie) et au moins un C à l'intérieur. Le joueur part de P et doit pouvoir atteindre le C puis le E sans traverser de mur.

§3.3 — Les 5 règles de validité

Pour qu'une map soit acceptée, toutes ces conditions doivent être vraies :

★ Les règles du sujet
  1. Exactement 1 sortie E
  2. Exactement 1 départ P
  3. Au moins 1 collectible C
  4. La map est rectangulaire (toutes les lignes de même longueur)
  5. La map est entièrement entourée de murs 1

Et deux conditions « algorithmiques » en plus :

  • La map ne contient que les 5 caractères autorisés
  • Il existe un chemin valide : depuis P, on peut atteindre E et tous les C (→ chap. 05, le flood fill)
★ Doublons
Le sujet précise : si la map contient des caractères en double qui devraient être uniques (plusieurs P ou plusieurs E), il faut afficher une erreur. Donc on compte : P == 1, E == 1, C >= 1.

§3.4 — Galerie d'invalides

Savoir ce qui doit échouer est aussi important que le cas qui marche. Voici des maps à rejeter :

✗ Pas fermée (trou dans le mur)

11111 10C00 ← bord droit pas un mur 1P0E1 11111

✗ Pas rectangulaire

1111111 1P0C001 10E11 ← ligne plus courte 1111111

✗ Pas de collectible

11111 1P0E1 11111 ← aucun C → invalide

✗ Deux joueurs

1111111 1P0C0P1 ← 2 P → invalide 100E001 1111111

✗ Chemin bloqué par un mur

1111111 1P011C1 ← C inaccessible (mur entre P et C) 10011E1 1111111

§3.5 — La gestion d'erreur attendue

★ Format imposé
En cas de map invalide (ou d'argument foireux), le programme doit quitter proprement et afficher "Error\n" suivi d'un message explicite de ton choix sur la ligne suivante. Exemple : 
Error
Map is not rectangular
★ Détail souvent oublié
Vérifie aussi l'extension du fichier : l'argument doit finir par .ber. Un argument map.txt ou sans argument du tout doit produire une erreur propre, pas un crash.

§3.6 — Récap

★ À retenir
  • 5 chars seulement : 0 1 C E P
  • 1 P, 1 E, ≥1 C
  • Rectangulaire + entourée de murs
  • Chemin valide vers E et tous les C (chap. 05)
  • Erreur = "Error\n" + message explicite, sortie propre
  • Vérifier aussi l'extension .ber
