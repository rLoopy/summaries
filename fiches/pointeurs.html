🧠 1. Le modèle mental

La mémoire = une rue avec des maisons numérotées. Chaque maison peut contenir une valeur.

// après : int a = 42; 0x100 : [ 42 ] ← a vit ici 0x104 : [ ... ] 0x108 : [ ... ]

Un pointeur = une variable qui, au lieu de stocker une valeur, stocke l'adresse d'une autre variable.

// après : int a = 42; int *p = &a; 0x100 : [ 42 ] ← a 0x108 : [ 0x100 ] ← p, contient l'adresse de a

📝 Donc : p ne contient pas 42. p contient 0x100 (l'adresse de a). Pour obtenir la valeur 42, il faut déréférencer p.

🔧 2. Les 2 opérateurs magiques — & et *

&x — "donne-moi l'ADRESSE de x"

S'utilise sur une variable. Retourne un pointeur.

int a = 42; int *p = &a; // p reçoit l'adresse de a printf("%p", &a); // affiche 0x7ffeef3a1c28 (ou autre)

*p — "donne-moi la VALEUR à l'adresse stockée dans p"

S'utilise sur un pointeur. C'est le déréférencement. Ouvre la maison pointée.

int a = 42; int *p = &a; printf("%d", *p); // affiche 42 (va à l'adresse dans p, lit la valeur) *p = 99; // écrit 99 à l'adresse dans p → a devient 99

🎯 Règle mnémotechnique : & et * sont des inverses.
Si p = &a, alors *p == a et &(*p) == p. Toujours.

⭐ 3. L'étoile — LE piège qui fait douter

L'étoile * fait deux choses très différentes selon où elle est.

Dans une DÉCLARATION
int *p;

= "p est un pointeur vers int".
L'étoile fait partie du type.

Dans le code après
*p = 99;

= "déréférence p, écris 99 là-bas".
L'étoile est l'opérateur deref.

Les 2 sources de confusion

int *p = &a;

Déclare p comme pointeur, l'init avec l'adresse de a.
L'étoile ici = je suis un pointeur.

*p = 99;

Utilise p (déjà déclaré), écris 99 à l'adresse dans p.
L'étoile ici = déréférence.

🤔 Quiz : quelle ligne déclare un pointeur ?
(A) int *p = &a; (B) *p = 99; (C) p = &a; (D) int p;
voir la réponse
A déclare un pointeur (int * est le type).
B utilise un pointeur déjà déclaré (deref).
C réassigne un pointeur existant (change l'adresse dans p).
D déclare un int normal — pas un pointeur (pas d'étoile).

🎯 4. Les 4 opérations avec un pointeur

Étant donné int a = 5; int b = 10; int *p = &a;

// opération 1 : changer la VALEUR pointée (modifie a) *p = 99; // a devient 99, p intact, b intact // opération 2 : changer l'ADRESSE dans p (p pointe ailleurs) p = &b; // p pointe maintenant sur b, a intact // opération 3 : LIRE la valeur pointée int x = *p; // x reçoit la valeur à l'adresse dans p // opération 4 : LIRE l'adresse dans p printf("%p", p); // affiche l'adresse contenue dans p

La confusion classique : *p = 99 vs p = 99.

*p = 99; ✅

Déréférence p, écris 99 à l'adresse pointée. a devient 99.

p = 99; 💥

Met 99 dans p (comme si c'était une adresse). Compile error avec -Werror. Forcé → segfault à la prochaine deref.

🔍 5. int p vs int *p — la distinction fondamentale

int p; — un entier simple

Taille : 4 octets (sur la plupart des systèmes).
Contient un nombre.
Ops permises : +, -, *, /, etc.
Pas de deref possible.

int *p; — un pointeur

Taille : 8 octets (sur 64-bit).
Contient une adresse.
Ops permises : *p (deref), p = &x (réassigner).
Arithmétique spéciale : p + 1 avance de sizeof(int) octets.

⚠️ Le piège des déclarations multiples

Attention à où tu mets l'étoile quand tu déclares plusieurs variables sur la même ligne :

int* p, q; // PIÈGE : p est int*, q est int (PAS pointeur) int *p, *q; // OK : 2 pointeurs. Style 42 / K&R.

Convention 42 : toujours écrire int *p (étoile collée au nom), pour éviter ce piège.

💡 6. Pourquoi les pointeurs existent — passage par valeur vs référence

En C, quand tu passes un argument à une fonction, c'est par valeur. La fonction reçoit une copie.

void try_modify(int x) { x = 999; } int main(void) { int a = 5; try_modify(a); printf("a = %d\n", a); // affiche 5, PAS 999 }

Pourquoi ? La fonction a reçu une copie de 5, l'a modifiée en 999. Mais le a de main est une autre boîte, intacte.

La solution : passer l'ADRESSE, pas la valeur

void modify_via_ptr(int *x) { *x = 999; // écris à l'adresse reçue } int main(void) { int a = 5; modify_via_ptr(&a); // on passe l'adresse de a printf("a = %d\n", a); // affiche 999 }

Là, la fonction reçoit une copie de l'adresse de a. Elle déréférence, écrit à cette adresse → le vrai a de main est modifié.

🎯 C'est pour ça que les pointeurs existent : permettre à une fonction de modifier une variable de l'appelant. Sans pointeurs, impossible (sauf via des valeurs de retour).

⚡ 7. Double pointeur — int **pp

Juste un pointeur qui pointe sur un autre pointeur. Pareil, mais un niveau de plus.

int a = 42; int *p = &a; // p pointe sur a int **pp = &p; // pp pointe sur p // la chaîne d'indirection : printf("%d", a); // 42 printf("%d", *p); // 42 (déréférence une fois) printf("%d", **pp); // 42 (déréférence deux fois)

Quand t'en as besoin ?

  • Quand une fonction doit modifier un pointeur de l'appelant (genre faire pointer la tête de liste ailleurs). Exemple : ft_list_push_front(t_list **head, void *data) — le ** permet à la fonction de changer ce sur quoi head pointe.
  • Tableaux de strings : char **argv (tableau de pointeurs sur char).
  • Grilles 2D allouées dynamiquement.

📝 Pour push_swap : tu vas voir t_list **stack_a si tu implémentes des fonctions qui peuvent remplacer la tête de pile (ex: pa, pb).

⚠️ 8. Les pièges classiques

Pointeur non initialisé

int *p; // p contient UNE ADRESSE ALÉATOIRE (garbage) *p = 42; // 💥 écris à une adresse aléatoire → segfault (ou pire)

Règle : initialise toujours. int *p = NULL; ou int *p = &truc;.

Pointeur NULL

int *p = NULL; *p = 42; // 💥 déréférence NULL = segfault garanti

Règle : avant de deref, check if (p) ou if (p != NULL).

Dangling pointer (pointeur en l'air)

int *p = malloc(sizeof(int)); *p = 42; free(p); // mémoire libérée *p = 99; // 💥 p existe encore mais pointe sur de la mémoire libérée

Règle : après free(p), mets p = NULL. Comme ça une deref suivante = segfault clair, pas corruption silencieuse.

Retourner un pointeur sur variable locale

int *foo(void) { int x = 42; return &x; // 💥 x meurt à la fin de foo, l'adresse devient invalide }

Règle : si tu veux retourner un pointeur sur qqch qui survit, utilise malloc (heap) au lieu d'une variable locale (stack).

🤔 Quiz final : trouve les bugs dans ce code
int *p; *p = 42; int a = 5; p = a; printf("%d", *p);
voir les bugs
Bug 1 : int *p; — p non initialisé, contient du garbage.
Bug 2 : *p = 42; — deref d'un pointeur garbage → segfault immédiat.
Bug 3 : p = a; — assigne un int (5) à un pointeur. Compile error avec -Werror. Sans cast, "assignment makes pointer from integer without a cast".
Bug 4 : même si les bugs précédents étaient fix, la dernière ligne ferait segfault (p pointerait sur l'adresse 5, invalide).

Version corrigée :
int a = 5; int *p = &a; *p = 42; // a devient 42 printf("%d", *p); // affiche 42

✦ Règles d'or

  • Toujours initialiser un pointeur (NULL ou adresse valide).
  • Avant de deref, check NULL si pas sûr.
  • Après free(p), fais p = NULL.
  • Style 42 : int *p, étoile collée au nom.
  • L'étoile dans la déclaration ≠ l'étoile dans le code.
  • Si ça compile pas → relis le message d'erreur avant de paniquer. Souvent c'est un & manquant ou un * en trop.
