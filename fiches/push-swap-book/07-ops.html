Les 11 opérations

recâblage de pointeurs étape par étape pour chaque op

7.1Vue d'ensemble — 4 familles + pattern commun

Les 11 ops se répartissent en 4 familles, chacune dans son fichier :

FamilleFichierOpsHelper static
swap (échange top et 2e)op_swap.csa, sb, ssswap_top
push (déplace 1 node entre piles)op_push.cpa, pbpush_top
rotate (1er → dernier)op_rotate.cra, rb, rrrotate
reverse rotate (dernier → 1er)op_reverse.crra, rrb, rrrreverse_rotate

Le pattern uniforme

Chaque fichier suit le même squelette :

/* helper static : la logique pure, sans I/O */
static void do_op(t_stack **stack)
{
    /* logique de l'opération */
}

/* wrapper public : appelle le helper + write le nom */
void xa(t_stack **a)
{
    do_op(a);
    write(1, "xa\n", 3);
}

L'idée : la logique d'op n'a pas à savoir si elle fait sa ou sb. Elle fait le travail de "swap les 2 premiers de cette pile", peu importe quelle pile. C'est le wrapper qui sait quel nom écrire sur stdout.

Bénéfices :

  • DRY : code de logique écrit une seule fois
  • Norme : ≤ 5 fonctions par fichier
  • Test : on peut tester le helper sans avoir le bruit du write

7.2swap (sa/sb/ss)

Définition

sa = "swap les 2 premiers éléments de a". Si la pile a 0 ou 1 élément, ne fait rien.

avant sa : [3, 1, 4, 2] après sa : [1, 3, 4, 2] ↑ ↑ les 2 premiers échangés, le reste intact

L'astuce : value swap au lieu de pointer swap

Pour échanger les 2 premiers nodes, deux approches possibles :

Pointer swap (compliqué)

Recâbler les next pour que :

  • Le 2e node devienne le head
  • Le 1er node devienne le 2e
  • Le 3e reste 3e

→ 4 lignes de manipulation de pointeurs, facile à se tromper.

Value swap (notre choix)

Échanger juste les valeurs des 2 nodes :

tmp = a->val;
a->val = a->next->val;
a->next->val = tmp;

→ 3 lignes, pas de pointer juggling, pas de risque de bug. Les nodes restent à leurs adresses, seules les valeurs bougent.

On choisit l'approche value swap.

Le helper swap_top

static void swap_top(t_stack **stack)
{
    int     tmp;

    if (!*stack || !(*stack)->next)
        return ;
    tmp = (*stack)->val;
    (*stack)->val = (*stack)->next->val;
    (*stack)->next->val = tmp;
}

Décortiquage :

  • if (!*stack || !(*stack)->next) return ; : garde-fou. Si la pile est vide ou n'a qu'un seul élément, on ne fait rien (conforme au sujet).
  • Pattern de swap classique en 3 lignes avec tmp.
  • Note les parenthèses obligatoires : (*stack)->val, pas *stack->val.

Les wrappers

void sa(t_stack **a)
{
    swap_top(a);
    write(1, "sa\n", 3);
}

void sb(t_stack **b)
{
    swap_top(b);
    write(1, "sb\n", 3);
}

void ss(t_stack **a, t_stack **b)
{
    swap_top(a);
    swap_top(b);
    write(1, "ss\n", 3);
}

ss appelle le helper sur les 2 piles, puis écrit "ss" UNE SEULE FOIS sur stdout (pas "sa" puis "sb"). Bien lire la spec.

7.3push (pa/pb)

Définition

pb = "prends le top de a et mets-le au top de b". Si a est vide, ne fait rien. pa = l'inverse.

avant pb : a = [3, 1, 4] b = [9, 7] après pb : a = [1, 4] b = [3, 9, 7] ↑ ↑ 3 a été retiré 3 est arrivé en top

Le helper push_top — 4 étapes critiques

Ici, value swap ne marche pas : on doit vraiment déplacer un node d'une pile à l'autre. On manipule des pointeurs.

static void push_top(t_stack **dst, t_stack **src)
{
    t_stack *top;

    if (!*src)
        return ;
    top = *src;
    *src = top->next;
    top->next = *dst;
    *dst = top;
}

Les 4 étapes du recâblage

État initial : src → [X] → [Y] → [Z] → NULL et dst → [A] → [B] → NULL.

Étape 1 : top = *src;

On sauvegarde l'adresse du top de src dans une variable locale top. Maintenant top pointe sur [X].

Étape 2 : *src = top->next;

On déplace le head de src vers le suivant. Maintenant *src → [Y]. Le node [X] est "détaché" de src (mais on garde sa référence dans top).

Étape 3 : top->next = *dst;

On chaîne [X] devant l'ancien head de dst. Maintenant top → [X] → [A] → [B] → NULL.

Étape 4 : *dst = top;

On dit à dst : "ton nouveau head, c'est top". Maintenant *dst → [X] → [A] → [B] → NULL.

Schéma de transition

avant : *src → [X] → [Y] → [Z] *dst → [A] → [B] → NULL étape 1 : top = *src *src → [X] → [Y] → [Z] top → [X] étape 2 : *src = top->next *src → [Y] → [Z] top → [X] → [Y] (mais X n'est plus dans src) étape 3 : top->next = *dst top → [X] → [A] → [B] *dst → [A] → [B] étape 4 : *dst = top *src → [Y] → [Z] *dst → [X] → [A] → [B]

👉 Animation détaillée : push operation step-by-step

L'ordre des étapes est critique

Si tu inverses 2 et 3, par exemple, tu casses tout :

/* ❌ ordre incorrect */
top = *src;
top->next = *dst;     // top->next change, mais src->next pointe ENCORE sur top
*src = top->next;     // *src = *dst maintenant — la chaîne src est cassée

L'ordre 1 → 2 → 3 → 4 est le seul qui fonctionne. Mémorise ce pattern, c'est exactement le même qu'on retrouvera ailleurs.

Les wrappers

void pa(t_stack **a, t_stack **b)
{
    push_top(a, b);    // dst=a, src=b → top de b va dans a
    write(1, "pa\n", 3);
}

void pb(t_stack **a, t_stack **b)
{
    push_top(b, a);    // dst=b, src=a → top de a va dans b
    write(1, "pb\n", 3);
}

Note bien : pa et pb prennent les mêmes paramètres (a, b), mais les passent au helper dans un ordre différent. pa = "push vers a" = a est dst. pb = "push vers b" = b est dst.

7.4rotate (ra/rb/rr)

Définition

ra = "tous les éléments montent d'un cran, le 1er passe à la fin".

avant ra : [3, 1, 4, 2] après ra : [1, 4, 2, 3] ↑ ↑ 3 disparait, est repassé à la fin

Le helper rotate — 5 étapes

static void rotate(t_stack **stack)
{
    t_stack *first;
    t_stack *last;

    if (!*stack || !(*stack)->next)
        return ;
    first = *stack;
    *stack = first->next;
    last = *stack;
    while (last->next)
        last = last->next;
    last->next = first;
    first->next = NULL;
}

5 étapes (après le garde-fou) :

  1. Sauvegarder le 1er : first = *stack; — on garde sa référence parce qu'on va le déplacer à la fin
  2. Avancer le head : *stack = first->next; — le 2e devient le nouveau head
  3. Trouver le dernier : last = *stack; while (last->next) last = last->next; — on parcourt jusqu'au node dont next == NULL
  4. Attacher first au bout : last->next = first; — la chaîne s'allonge d'un cran
  5. first devient le nouveau bout : first->next = NULL; — important pour éviter la boucle infinie (sinon first pointe encore sur l'ancien 2e)

Le piège de l'étape 5

Si tu oublies first->next = NULL, voilà ce qui se passe :

après étape 4, sans étape 5 : *stack → [1] → [4] → [2] → [3] → [1] → [4] → [2] → [3] → ... ↑ first->next pointe encore sur [1] !

Boucle infinie. Le node [3] (= first) pointe encore sur [1] (son ancien next), donc [3] et [1] forment un cycle.

L'étape 5 coupe ce lien : first->next = NULL → [3] devient officiellement la fin de la chaîne.

7.5reverse_rotate (rra/rrb/rrr)

Définition

rra = "le dernier passe en 1er". L'inverse de ra.

avant rra : [3, 1, 4, 2] après rra : [2, 3, 1, 4] ↑ ↑ 2 arrive en top, 4 plus à la fin

Le helper reverse_rotate — 6 étapes

static void reverse_rotate(t_stack **stack)
{
    t_stack *cur;
    t_stack *last;

    if (!*stack || !(*stack)->next)
        return ;
    cur = *stack;
    while (cur->next->next)
        cur = cur->next;
    last = cur->next;
    cur->next = NULL;
    last->next = *stack;
    *stack = last;
}

La différence avec rotate

Avec rotate, on s'arrêtait sur le dernier node (while (last->next)). Avec reverse_rotate, on s'arrête sur l'avant-dernier (while (cur->next->next)).

Pourquoi ? Parce qu'on veut déconnecter le dernier de l'avant-dernier. Pour ça, on doit avoir une référence à l'avant-dernier pour pouvoir mettre cur->next = NULL.

Les 6 étapes

  1. Init curseur : cur = *stack;
  2. Marche jusqu'à l'avant-dernier : while (cur->next->next) cur = cur->next; — à la sortie, cur->next->next == NULL, donc cur->next est le dernier.
  3. Sauvegarder le dernier : last = cur->next;
  4. Déconnecter le dernier : cur->next = NULL; — maintenant l'avant-dernier devient le nouveau bout.
  5. Chaîner last devant l'ancien head : last->next = *stack;
  6. last devient le nouveau head : *stack = last;

Schéma de transition

avant : *stack → [A] → [B] → [C] → [D] → NULL étape 1-2 : cur = *stack, avance jusqu'à l'avant-dernier cur → [C] (cur->next = [D], cur->next->next = NULL → exit) étape 3 : last = cur->next last → [D] étape 4 : cur->next = NULL *stack → [A] → [B] → [C] → NULL et last → [D] (orphelin) étape 5 : last->next = *stack last → [D] → [A] → [B] → [C] → NULL *stack → [A] (toujours) étape 6 : *stack = last *stack → [D] → [A] → [B] → [C] → NULL

★ Note sur le nombre d'octets
Pour write, le 3e argument est le nombre d'octets à écrire. "sa\n" = 3 octets (s, a, \n). "rra\n" = 4 octets. Toujours compter \n.

7.6Le write à la fin — pourquoi

Chaque op imprime son nom sur stdout. C'est le cœur du sujet : le programme push_swap ne trie pas, il affiche les instructions de tri. Le checker exécutera ces instructions et vérifiera le résultat.

Cas spécial : si le helper ne fait rien (pile vide), on imprime quand même ? Oui, parce que le helper a la condition de garde mais le wrapper imprime quoi qu'il arrive.

/* Exemple : sa sur pile vide */
t_stack *a = NULL;
sa(&a);
// swap_top fait rien (garde-fou)
// MAIS write(1, "sa\n", 3) s'exécute → stdout aura "sa"
⚠ Conséquence pratique
On ne doit jamais appeler une op dans un contexte où elle ne ferait rien — sinon on imprime une op inutile qui gonfle le compteur. Dans le tri, on prend soin de tester les conditions avant chaque op (genre if ((*a)->val > (*a)->next->val) sa(a);).

Pourquoi write et pas printf ?

Le sujet interdit printf. On utilise write (fonction système basse-niveau, autorisée par la liste des fonctions externes).

Signature : ssize_t write(int fd, const void *buf, size_t count);

  • fd = 1 : stdout
  • fd = 2 : stderr
  • buf : pointeur sur les données à écrire
  • count : nombre d'octets

7.7Récap des 11 ops

★ Les techniques par famille
  • swap (sa/sb/ss) : value swap avec tmp, 3 lignes, pas de pointer juggling.
  • push (pa/pb) : 4 étapes de recâblage : save top, avancer src, lier top → dst, dst = top.
  • rotate (ra/rb/rr) : 5 étapes : save first, avancer head, marche au dernier, attache, first.next = NULL.
  • reverse rotate (rra/rrb/rrr) : 6 étapes, condition while (cur->next->next) pour s'arrêter sur l'avant-dernier.
★ Le pattern universel des fichiers op_*.c
Chaque fichier : 1 helper static + N wrappers publics. Total ≤ 5 fonctions, conforme à la norme. Le helper fait le travail, le wrapper ajoute le write.
Auto-éval
Pourquoi value swap pour sa au lieu de pointer swap ?
Beaucoup plus simple : 3 lignes au lieu de 4+ avec moins de risque de bug. Les nodes restent à leurs adresses, seules les valeurs internes changent. Pour sa, le résultat visible est identique (le top et le 2e sont échangés). C'est un cas où la solution la moins "puriste" est la meilleure.
Pourquoi rotate a 5 étapes et reverse_rotate en a 6 ?
Différence dans la stratégie de parcours :
rotate : on s'arrête sur le dernier (while (last->next)), on attache first derrière, on coupe son next.
reverse_rotate : on s'arrête sur l'avant-dernier (while (cur->next->next)), on sauvegarde le dernier, on coupe le lien, on rechaîne devant le head. Une étape de plus parce qu'on doit gérer 2 nodes (cur et last) au lieu d'un (first).
Pourquoi le helper est static ?
Pour qu'il soit invisible des autres fichiers (linkage interne) et que le compilateur puisse l'optimiser. Il ne doit pas être dans le header public. Et ça nous laisse les 5 fonctions de la norme pour les wrappers + le helper.
Si je veux savoir si la pile a a au moins 2 éléments avant sa, qu'est-ce que je teste ?
if ((*a) && (*a)->next) — ça vérifie que *a n'est pas NULL ET que le 2e node existe ((*a)->next non NULL). Si l'une des 2 conditions échoue, on n'a pas 2 éléments.
