PARTIE I · CHAPITRE 01

La mémoire et les pointeurs

le chapitre qui débloque tout — on part vraiment de zéro

1.1La RAM, c'est quoi ?

Quand ton programme tourne, il a besoin d'un endroit pour stocker des trucs temporairement : la valeur d'une variable, l'adresse d'un node, le résultat d'un calcul. Cet endroit, c'est la RAM (mémoire vive).

Imagine la RAM comme une immense rangée de casiers numérotés. Chaque casier peut contenir un octet (8 bits, c'est-à-dire un petit nombre entre 0 et 255).

RAM (vue simplifiée — chaque case = 1 octet)
0x0000?
0x0001?
0x0002?
0x0003?
…
0x7FA0?
…
0xFFFF?

Chaque casier a une adresse unique, écrite en hexadécimal (notation 0x suivie de chiffres et lettres). Par exemple : 0x7FA0 est juste un numéro de casier, comme la maison n°7FA0 dans une rue très longue.

★ Pourquoi hexadécimal ?
Parce que la mémoire fonctionne en binaire (puissances de 2), et l'hexadécimal compresse joliment le binaire (4 bits = 1 chiffre hexa). Tu n'as pas à te soucier de ça pour push_swap, c'est juste une convention de notation.

Le système choisit où mettre les choses

Quand tu écris int x = 42;, tu n'as aucun contrôle sur l'endroit où le système va stocker x. Il choisit un casier libre, met 42 dedans, et associe le nom x à cette adresse pour la durée de vie de la variable.

★ À retenir
  • Adresse = le numéro du casier (où c'est)
  • Valeur = ce qu'il y a dans le casier (quoi)
Deux concepts complètement différents qu'on va confondre toute la suite si on ne fait pas attention.

1.2Une variable, ça vit où ?

Quand tu déclares int x = 42;, voilà ce qui se passe concrètement :

  1. Le compilateur dit au système : "réserve-moi 4 octets consécutifs quelque part en RAM"
  2. Le système choisit, disons, les casiers 0x100 à 0x103
  3. Le compilateur écrit 42 dans ces 4 octets (en binaire, ça tient sur 32 bits)
  4. Il associe le nom x à l'adresse 0x100
après int x = 42;
0x100 42
← c'est la variable x

À partir de maintenant, chaque fois que tu écris x dans ton code, le compilateur sait que ça veut dire "va chercher la valeur au casier 0x100".

💡 Détail visuel
Un int prend en réalité 4 octets (32 bits), donc x occupe 0x100, 0x101, 0x102, et 0x103. On a juste écrit "0x100" pour simplifier — c'est l'adresse de départ.

1.3Adresse vs valeur

Avec une variable, tu peux faire deux choses bien distinctes :

OpérationNotation CCe que ça donne
Lire la valeurx42 (la valeur stockée)
Récupérer son adresse&x0x100 (où c'est)

L'opérateur & veut dire "adresse-de". Tu le connais déjà même sans le savoir, depuis scanf("%d", &x); en débutant.

int x = 42;
printf("valeur de x : %d\n", x);    // 42
printf("adresse de x : %p\n", &x);  // 0x100 (par exemple)
Auto-éval : si int y = 7; est stockée à 0x200...
...que valent y et &y ?
y vaut 7 (la valeur stockée).
&y vaut 0x200 (l'adresse où vit la variable).

1.4Les types et leur taille

Toutes les variables ne prennent pas la même place. Le type détermine combien d'octets sont réservés et comment interpréter les bits dedans.

TypeTaille typiquePlage
char1 octet (8 bits)-128 à 127 (ou 0 à 255 en unsigned)
short2 octets-32 768 à 32 767
int4 octets-2 147 483 648 à 2 147 483 647 (INT_MIN à INT_MAX)
long8 octets (sur Linux 64-bit)environ ±9.2 × 1018
int * (pointeur)8 octets sur 64-bit, 4 sur 32-bitune adresse mémoire
★ Important pour push_swap
Les arguments arrivent en char * et on doit les convertir en int. Mais pour détecter si quelqu'un passe un nombre plus grand que INT_MAX, on convertit d'abord en long (qui a 8 octets, donc beaucoup plus de plage), puis on compare aux limites. C'est pour ça qu'on a ft_atol (a-to-long) et pas ft_atoi dans le projet.

L'opérateur sizeof te donne la taille d'un type en octets :

sizeof(int)       // 4
sizeof(char)      // 1
sizeof(t_stack)   // 16 (4 pour val + 8 pour next + 4 padding)

1.5Les pointeurs — le concept

Un pointeur, c'est une variable comme une autre, sauf que la valeur qu'elle stocke est une adresse, pas un "vrai" nombre.

Si int x = 42; stocke 42, alors :

int *p = &x;  // p stocke L'ADRESSE de x

État mémoire après ces deux lignes :

après int x = 42; int *p = &x;
0x100 42
← x

0x500 0x100
← p (contient l'adresse de x)

p vit à sa propre adresse (0x500 ici), et son contenu est 0x100 (= l'adresse de x). On dit que p "pointe sur" x.

★ Analogie
Un pointeur, c'est comme un papier sur lequel tu as noté l'adresse d'une maison. Le papier lui-même est quelque part (sur ton bureau), mais ce qui est écrit dessus, c'est l'adresse d'une autre maison.

Pourquoi on a besoin de pointeurs ?

  • Pour pouvoir modifier une variable depuis une autre fonction (voir §1.13)
  • Pour construire des structures dynamiques comme les linked lists (chaque node a un pointeur vers le suivant)
  • Pour gérer de la mémoire à durée variable via malloc (§1.12)

1.6Déclarer un pointeur : la syntaxe

Pour déclarer un pointeur, on écrit le type pointé, suivi d'une étoile, suivi du nom :

int  *p;       // p est un pointeur vers int
char *s;       // s est un pointeur vers char (= une chaîne)
t_stack *node;  // node est un pointeur vers t_stack
int  **pp;      // pp est un pointeur vers pointeur vers int
💡 Lecture de droite à gauche
Lis int **pp de droite à gauche : "pp, c'est un pointeur (*), vers un pointeur (*), vers un int". C'est mécanique : compte les étoiles, c'est le nombre de niveaux d'indirection.

Initialiser un pointeur

Un pointeur déclaré sans valeur contient des octets aléatoires (= n'importe quoi). Tu ne dois jamais l'utiliser tant que tu ne lui as pas assigné une vraie adresse.

int *p;             // p contient des octets aléatoires : DANGER
*p = 42;            // CRASH ou comportement indéfini !

int x = 42;
int *p = &x;        // p contient maintenant une adresse valide
*p = 99;            // OK : on écrit 99 à l'adresse de x → x vaut maintenant 99

1.7Les 2 jobs du *

C'est LE piège du C qui fait tomber tout le monde. Le symbole * a deux significations complètement différentes selon où il apparaît.

JOB 1 — Dans un type

Le * dit "pointeur vers". C'est une description passive du type.

int *p;

→ "p est de type pointeur vers int".

Tu peux te repérer : il y a un type juste avant (int, char, t_stack...).

JOB 2 — Dans une expression

Le * dit "va voir ce qu'il y a à cette adresse". C'est une action.

*p = 99;

→ "va à l'adresse stockée dans p, écris 99".

Tu peux te repérer : il n'y a pas de type juste avant.

Test mental

int *p;       // "int" devant → c'est un type → "p est un pointeur vers int"
*p = 42;     // pas de type devant → c'est une action → "écris 42 à l'adresse dans p"

t_stack **stack;  // type → "stack est pointeur vers pointeur vers t_stack"
*stack = new;     // expression → "écris new à l'adresse dans stack"
★ La règle magique
Chaque * dans une expression enlève une étoile au type :
  • stack est de type t_stack **
  • *stack est de type t_stack * (une étoile en moins)
  • **stack est de type t_stack (deux étoiles en moins)
C'est l'inverse de la déclaration où chaque * en ajoute un.
Auto-éval
Dans char **argv, combien de niveaux d'indirection ?
2. argv est de type char **. Donc *argv est un char * (= une chaîne, le premier argument), et **argv est un char (le premier caractère du premier argument).

1.8L'opérateur & (adresse-de)

On a vu &x dans la §1.3, formalisons. L'opérateur & appliqué à une variable retourne son adresse en mémoire.

int x = 42;          // x à l'adresse 0x100
int *p;
p = &x;             // p reçoit 0x100, donc p pointe sur x

Quelques cas concrets dans push_swap :

parse_args(argc, argv, &n);       // on passe l'adresse de n pour que parse_args puisse modifier n
stack_free(&a);                    // on passe l'adresse de a pour que stack_free puisse mettre a à NULL
sort(&a, &b);                       // même logique pour les piles a et b
💡 Mnémo
Le & ajoute un niveau d'indirection (transforme un X en X *).
Le * dans une expression enlève un niveau (transforme un X * en X).
Ils sont l'inverse l'un de l'autre.

1.9Déréférencer (*p)

"Déréférencer", c'est suivre le pointeur jusqu'à la cible pour lire ou écrire ce qu'il y a là-bas.

Lire à travers un pointeur

int x = 42;
int *p = &x;

printf("%d\n", *p);   // "va à l'adresse dans p et lis la valeur" → 42

Écrire à travers un pointeur

int x = 42;
int *p = &x;

*p = 99;              // "va à l'adresse dans p et écris 99 là-bas"
printf("%d\n", x);    // 99 — on a bien modifié x via le pointeur p

État mémoire :

avant : 0x100: 42 (x) 0x500: 0x100 (p) après *p = 99 : 0x100: 99 (x — modifié !) 0x500: 0x100 (p — inchangé)
⚠ Le piège du pointeur NULL
Si p vaut NULL (ou contient une adresse invalide), *p provoque un segfault immédiat. Toujours tester un pointeur avant de le déréférencer si tu n'es pas sûr : 
if (p != NULL)
    *p = 99;

1.10Pointeurs vers pointeurs (**)

Un pointeur peut pointer sur n'importe quoi, y compris sur un autre pointeur.

int x = 42;       // x à 0x100
int *p = &x;     // p à 0x500, contient 0x100
int **pp = &p;   // pp à 0x900, contient 0x500

Trois niveaux d'indirection :

pp ──► 0x500 ──► 0x100 ──► 42 (adresse de p) (adresse de x) (valeur de x) pp = 0x500 (adresse de p) *pp = 0x100 (= valeur de p = adresse de x) **pp = 42 (= valeur de x)
ExpressionTypeValeur
ppint **0x500 (adresse de p)
*ppint *0x100 (valeur de p, = adresse de x)
**ppint42 (valeur de x)
★ Pourquoi t'aurais besoin de ** ?
Une raison principale : pouvoir modifier la valeur d'un pointeur depuis une autre fonction. En push_swap, c'est exactement ce qu'on fait avec t_stack **stack dans stack_add_bottom, stack_free, etc. On y revient en §1.14.

1.11Stack vs Heap (deux zones de mémoire)

Toute la mémoire de ton programme n'est pas pareille. Il y a deux grandes zones, avec des règles différentes :

Stack (la pile d'appels)

  • C'est là que vivent les variables locales
  • Créée et détruite automatiquement à chaque entrée/sortie de fonction
  • Très rapide d'accès
  • Taille limitée (quelques Mo par défaut)
  • Tu n'as aucun contrôle dessus, c'est le compilateur qui décide

Heap (le tas)

  • C'est là que vivent les choses créées via malloc
  • Tu dois libérer manuellement avec free
  • Plus lent
  • Beaucoup plus grand (peut consommer toute la RAM disponible)
  • Survit à la fin de la fonction qui l'a créé
void demo(void)
{
    int  x = 42;                       // x vit sur la STACK
    int *p = malloc(sizeof(int));      // *p vit sur le HEAP
    *p = 99;

    // À la fin de la fonction :
    //   x disparaît automatiquement (stack unwind)
    //   *p existe TOUJOURS — c'est sur le heap, le système ne le libère pas tout seul
    //   → fuite mémoire si on ne fait pas free(p) !
}
⚠ Erreur classique : retourner l'adresse d'une variable locale
int *fonction_pourrie(void)
{
    int x = 42;
    return (&x);   // x meurt ici, on retourne un pointeur vers du vide
}
Le pointeur retourné pointe sur de la mémoire qui ne t'appartient plus. C'est un dangling pointer. Comportement indéfini (souvent crash, parfois pire : corruption silencieuse).

Pour qu'une variable survive à la fonction, elle doit être sur le heap (via malloc).

1.12malloc et free

malloc(n) demande n octets sur le heap et te retourne l'adresse du début de cette zone. Si la RAM est saturée, il retourne NULL.

int *p = malloc(sizeof(int));   // demande 4 octets pour stocker un int
if (!p)                          // si malloc a échoué (RAM pleine)
    return ;                      // on sort, sinon segfault à la ligne suivante
*p = 42;                        // écris 42 dans la zone allouée

// ... plus tard, quand on a fini avec p ...
free(p);                          // libère les 4 octets — sinon memory leak

L'astuce sizeof(*p)

Dans stack_new, tu vois malloc(sizeof(*node)) au lieu de malloc(sizeof(t_stack)). Les deux fonctionnent, mais le premier est plus robuste :

node = malloc(sizeof(*node));      // taille de ce que pointe node, peu importe le type
node = malloc(sizeof(t_stack));    // taille de t_stack — si tu changes le type, faut éditer ici

Le premier s'adapte tout seul si tu changes le type de node plus tard. C'est une convention défensive.

★ Règle d'or
Chaque malloc doit avoir son free correspondant. Sinon : memory leak. Le programme grossit jusqu'à manquer de RAM. valgrind est ton ami pour les détecter.

1.13Pass by value vs pass by pointer

En C, quand tu passes un argument à une fonction, la fonction reçoit une copie de la valeur. Si elle modifie la copie, ça ne change pas l'original.

void essayer_de_modifier(int x)
{
    x = 99;          // modifie la COPIE locale
}

int main(void)
{
    int a = 10;
    essayer_de_modifier(a);
    printf("%d\n", a);     // affiche 10, pas 99 !
}

Pour vraiment modifier a depuis une autre fonction, on passe son adresse :

void modifier_pour_de_vrai(int *x)
{
    *x = 99;          // "va à l'adresse reçue et écris 99"
}

int main(void)
{
    int a = 10;
    modifier_pour_de_vrai(&a);   // on passe l'adresse de a
    printf("%d\n", a);          // affiche 99 ✓
}

État mémoire de l'appel

main : a = 10 (à l'adresse 0x100) main appelle modifier_pour_de_vrai(&a) → passe 0x100 modifier_pour_de_vrai : x = 0x100 (adresse de a copiée dans le paramètre x) *x = 99 → va à 0x100, écrit 99 → modifie le a de main
★ La règle
Pour modifier une variable v depuis une fonction, il faut :
  1. Passer &v à la fonction
  2. Le paramètre est de type type * (un cran d'indirection de plus que v)
  3. Dans la fonction, on modifie via *param = ...

1.14Le pattern ** — modifier un pointeur

On a vu que pour modifier un int, on prend int *. Par extension :

Pour modifier...Le paramètre est de type...
int xint *
char *schar **
t_stack *stack (un pointeur vers un node)t_stack **

Exemple concret : stack_add_bottom

On veut une fonction qui ajoute un node à la pile a. La pile a est représentée par un pointeur vers le premier node (le head). Quand la pile est vide, on doit changer ce pointeur (le head est maintenant le nouveau node). Sinon on ne touche pas au head, on attache à la fin.

void stack_add_bottom(t_stack **stack, int val)
{
    // ...
    if (!*stack)            // si pile vide (le head est NULL)
        *stack = new;        // modifier le head depuis la fonction
    // ...
}

Appel :

t_stack *a = NULL;
stack_add_bottom(&a, 42);     // on passe &a (adresse de a), pas a

Lecture des expressions dans stack_add_bottom

ExpressionTypeCe que c'est
stackt_stack **L'adresse de la variable a de l'appelant
*stackt_stack *La variable a elle-même (le head de la pile)
**stackt_stackLe node head en entier (crash si *stack == NULL)
(*stack)->valintLa valeur du node head
⚠ Parenthèses obligatoires
L'opérateur -> est plus prioritaire que *. Donc *stack->val est interprété comme *(stack->val), ce qui n'a pas de sens (stack n'a pas de champ val, c'est un **). Il faut écrire (*stack)->val avec les parenthèses pour forcer le bon ordre.
Auto-éval finale du chapitre
Si stack_add_bottom(t_stack **stack, ...) et qu'on veut modifier le head, on écrit stack = ... ou *stack = ... ?
*stack = .... stack tout court ne modifierait que la copie locale du paramètre (qui meurt à la fin de la fonction). *stack déréférence pour atteindre la vraie variable de l'appelant.
Pour le test "pile vide", on écrit !stack ou !*stack ?
!*stack. La pile est vide si le head est NULL, et le head c'est *stack. !stack testerait si l'adresse même est NULL, ce qui n'arriverait que si quelqu'un appelait stack_add_bottom(NULL, 42) — un cas absurde.
Pour passer une variable t_stack *a en argument et permettre à la fonction de modifier a, on écrit l'appel comment ?
stack_add_bottom(&a, val); — avec l'opérateur & pour récupérer l'adresse de a.

1.15Récap du chapitre

★ Les 10 concepts à retenir
  1. La RAM = une rangée de casiers numérotés (octets).
  2. Chaque variable a une adresse (où) et une valeur (quoi).
  3. L'opérateur & donne l'adresse d'une variable.
  4. Un pointeur est une variable qui contient une adresse.
  5. Le * a 2 jobs : dans un type (description) vs dans une expression (action de déréférencement).
  6. Chaque * en expression enlève une étoile au type.
  7. Stack = mémoire auto, courte durée. Heap = mémoire malloc, longue durée.
  8. Pour modifier une variable depuis une fonction, passer &var et le paramètre est type *.
  9. Pour modifier un pointeur depuis une fonction, paramètre est type **.
  10. Parenthèses obligatoires : (*stack)->val, pas *stack->val.
