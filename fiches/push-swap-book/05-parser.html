PARTIE III · CHAPITRE 05

Parser & validator

de argv à un tableau d'int validé, en gérant tous les cas

5.1Le problème : argv → int[]

Quand tu lances ./push_swap 3 1 4 1 5, le système te donne en entrée :

argc = 6
argv = {"./push_swap", "3", "1", "4", "1", "5", NULL}

Mais pour construire ta pile, tu as besoin de :

values = {3, 1, 4, 1, 5}   // tableau d'int, taille n=5

Le job du parser, c'est cette transformation, en validant au passage que tout est correct (vrais entiers, dans la plage, pas de doublons).

Le problème supplémentaire : la chaîne unique

Le sujet impose que ./push_swap "3 1 4 1 5" marche aussi (un seul argument qui contient plusieurs nombres séparés par des espaces). On doit donc gérer 2 formats d'entrée différents.

5.2argv, c'est quoi exactement

argv est un tableau de chaînes (donc char **). Chaque entrée est un char * qui pointe sur une chaîne C (terminée par \0).

int main(int argc, char **argv)
  • argc = nombre d'arguments, y compris le nom du programme
  • argv[0] = le nom du programme ("./push_swap")
  • argv[1] = le 1er vrai argument
  • argv[argc] = NULL (sentinelle de fin)

Pour ./push_swap 3 1 4 :

argc = 4 argv: [0] = "./push_swap" [1] = "3" [2] = "1" [3] = "4" [4] = NULL ← sentinelle

Pour ./push_swap "3 1 4" :

argc = 2 argv: [0] = "./push_swap" [1] = "3 1 4" ← une seule chaîne avec espaces [2] = NULL

D'où la nécessité de notre tokenize qui distingue les 2 cas.

5.3tokenize — split sur les espaces

char **tokenize(int argc, char **argv)
{
    char    **tokens;
    int     i;

    if (argc == 2)
        return (ft_split(argv[1], ' '));
    tokens = malloc(sizeof(char *) * argc);
    if (!tokens)
        return (NULL);
    i = 0;
    while (i < argc - 1)
    {
        tokens[i] = ft_strdup(argv[i + 1]);
        i++;
    }
    tokens[argc - 1] = NULL;
    return (tokens);
}

Décortiquage

Cas 1 : argc == 2 (l'user a passé une seule chaîne).

if (argc == 2)
    return (ft_split(argv[1], ' '));

On délègue à ft_split de la libft, qui découpe la chaîne en morceaux selon le séparateur (' '). Le résultat est un char ** alloué, terminé par NULL. Parfait, c'est exactement ce qu'on veut.

Cas 2 : argc > 2 (plusieurs args séparés).

On construit nous-même un char ** en copiant chaque argv[i] avec ft_strdup (qui malloc + copie chaque chaîne). Pourquoi copier au lieu d'utiliser argv directement ? Pour avoir une structure homogène — peu importe le cas d'entrée, on a un char ** qu'on peut free uniformément ensuite avec free_tokens.

Schéma de résultat

Pour ./push_swap 3 1 4 :

tokens = {"3", "1", "4", NULL}
         ↑    ↑    ↑    ↑
        nouvelles chaînes mallocées + NULL final
★ Pourquoi NULL à la fin ?
Le NULL sert de sentinelle : ça permet de boucler sans connaître la longueur (juste tester si tokens[i] != NULL). C'est le même pattern que les chaînes C qui finissent par \0, ou les tableaux argv qui finissent par NULL.

5.4count_tokens — compter les éléments

int count_tokens(char **tokens)
{
    int     i;

    i = 0;
    while (tokens[i] != NULL)
        i++;
    return (i);
}

Parcours basique avec compteur, exactement comme strlen mais pour un tableau de chaînes. On s'arrête sur le NULL final.

Cette fonction est utile parce qu'après ft_split, on ne connaît pas a priori combien de tokens ont été produits (l'user a pu passer 3, 5, ou 100 nombres dans sa chaîne). On compte pour savoir.

5.5free_tokens — libérer le tableau

void free_tokens(char **tokens)
{
    int     i;

    if (!tokens)
        return ;
    i = 0;
    while (tokens[i])
    {
        free(tokens[i]);
        i++;
    }
    free(tokens);
}

Pourquoi 2 niveaux de free ?

tokens est un char ** = un tableau de pointeurs. Chaque case du tableau pointe sur une chaîne mallocée séparément. Il faut donc :

  1. D'abord free chaque chaîne individuelle (tokens[i])
  2. Puis free le tableau de pointeurs lui-même (tokens)

Si tu oublies la première étape, tu as un memory leak (les chaînes restent mallocées). Si tu inverses l'ordre, tu accèdes à tokens[i] après avoir libéré tokens → use-after-free.

tokens (char **) │ ▼ ┌──────┬──────┬──────┬──────┐ │ [0] │ [1] │ [2] │ NULL │ ← tableau mallocé └──┬───┴──┬───┴──┬───┴──────┘ │ │ │ ▼ ▼ ▼ "3\0" "1\0" "4\0" ← chaînes mallocées séparément free(tokens[0]) ← libère "3\0" free(tokens[1]) ← libère "1\0" free(tokens[2]) ← libère "4\0" free(tokens) ← libère le tableau

La protection if (!tokens) return ; au début est défensive : si jamais quelqu'un appelle free_tokens(NULL), on ne crash pas.

5.6is_number et is_valid_int

is_valid_int — vérifier le format

int is_valid_int(char *s)
{
    int     i;

    if (!s || !s[0])
        return (0);
    i = 0;
    if (s[0] == '+' || s[0] == '-')
        i = 1;
    if (!s[i])
        return (0);
    while (s[i])
    {
        if (!ft_isdigit(s[i]))
            return (0);
        i++;
    }
    return (1);
}

Cette fonction vérifie qu'une chaîne représente un nombre au sens syntaxique :

  1. Si chaîne NULL ou vide → invalide
  2. Si premier char est + ou -, on le skip (signe optionnel)
  3. Si après le signe il n'y a plus rien ("+" ou "-" tout seul) → invalide
  4. Tous les chars restants doivent être des chiffres (isdigit)

Exemples

EntréeRésultatPourquoi
"42"1 (valide)que des chiffres
"-42"1signe + chiffres
"+42"1signe + chiffres
""0chaîne vide
"-"0signe sans chiffre
"42a"0caractère non-numérique
"4 2"0espace au milieu
"2147483648"1 (format OK)mais hors plage int — détecté par is_number

is_number — vérifier le format ET la plage int

int is_number(char *s)
{
    long    n;

    if (!is_valid_int(s))
        return (0);
    n = ft_atol(s);
    if (n > INT_MAX || n < INT_MIN)
        return (0);
    return (1);
}

Deux étapes : d'abord on vérifie que le format est valide (signe + chiffres), puis on convertit en long et on compare aux limites de int.

★ Pourquoi long ?
Si on parsait directement en int, on aurait un overflow pour des valeurs hors plage. Exemple : "2147483648" (= INT_MAX + 1) parsé en int donnerait INT_MIN (rollover binaire), ce qu'on prendrait pour une valeur valide.

En long (8 octets, plage ~±9.2 × 1018), on a largement la marge pour parser sans overflow, et ensuite on compare aux limites INT_MAX/INT_MIN.

5.7ft_atol — chaîne vers long

long ft_atol(char *s)
{
    long    res;
    int     i;
    int     sign;

    sign = 1;
    i = 0;
    if (s[0] == '+' || s[0] == '-')
    {
        if (s[0] == '-')
            sign = -1;
        i = 1;
    }
    res = 0;
    while (s[i] >= '0' && s[i] <= '9')
    {
        res = res * 10 + (s[i] - '0');
        i++;
    }
    return (res * sign);
}

L'algorithme

  1. On gère le signe optionnel
  2. On part de res = 0
  3. Pour chaque chiffre :
    • multiplier le résultat actuel par 10 (= décalage à gauche)
    • ajouter la valeur numérique du chiffre courant
  4. Appliquer le signe à la fin

Déroulé concret : "42"

i=0, s[0]='4' : res = 0*10 + 4 = 4 i=1, s[1]='2' : res = 4*10 + 2 = 42 i=2, s[2]='\0' : sortie de boucle return 42 * 1 = 42

Déroulé : "-1234"

s[0]='-' : sign=-1, i=1 i=1, '1' : res = 0*10 + 1 = 1 i=2, '2' : res = 1*10 + 2 = 12 i=3, '3' : res = 12*10 + 3 = 123 i=4, '4' : res = 123*10 + 4 = 1234 i=5, '\0' : stop return 1234 * -1 = -1234
★ Le truc du s[i] - '0'
En ASCII, le caractère '0' a la valeur 48, '1' = 49, ..., '9' = 57. Donc '5' - '0' = 57 - 48 = 5 (la valeur numérique). C'est l'astuce pour convertir un char en int sans table de lookup.

5.8has_duplicates — détecter les doublons

int has_duplicates(int *values, int n)
{
    int     i;
    int     j;

    i = 0;
    while (i < n)
    {
        j = i + 1;
        while (j < n)
        {
            if (values[i] == values[j])
                return (1);
            j++;
        }
        i++;
    }
    return (0);
}

L'approche : O(n²) brute force

Pour chaque paire (i, j) avec i < j, on compare values[i] et values[j]. Si on trouve deux valeurs égales, on retourne 1 (= il y a un doublon).

Pourquoi pas un algo plus rapide (O(n log n)) ?

On pourrait trier le tableau et vérifier les voisins (mais on aurait modifié l'ordre des valeurs, problématique). Ou utiliser une table de hash. Mais :

  • Pour n ≤ 500, O(n²) = 250 000 comparaisons → quelques microsecondes. Largement assez rapide.
  • L'algo brute force tient en 11 lignes, sans alloc, sans dépendance.
  • Avantage : pas d'optim prématurée. Code clair.

Déroulé sur [3, 1, 4, 1, 5]

i=0 (val=3): j=1 (val=1): 3==1? non j=2 (val=4): 3==4? non j=3 (val=1): 3==1? non j=4 (val=5): 3==5? non i=1 (val=1): j=2 (val=4): 1==4? non j=3 (val=1): 1==1? OUI → return 1
★ Note : on s'arrête au premier doublon
Pas besoin de continuer une fois qu'on a trouvé un doublon. return 1 court-circuite tout. C'est une optim micro mais "free" — pas plus de code, juste un return placé au bon endroit.

5.9convert_tokens — chaînes vers entiers

int *convert_tokens(char **tokens, int n)
{
    int     *values;
    int     i;

    values = malloc(sizeof(int) * n);
    if (!values)
        return (NULL);
    i = 0;
    while (i < n)
    {
        if (!is_number(tokens[i]))
        {
            free(values);
            return (NULL);
        }
        values[i] = (int)ft_atol(tokens[i]);
        i++;
    }
    return (values);
}

L'algorithme

  1. Allouer un tableau d'int de taille n
  2. Pour chaque token :
    • vérifier que c'est un vrai nombre dans la plage int via is_number
    • si non, libérer ce qu'on a déjà alloué et retourner NULL (= erreur)
    • sinon, parser en long puis cast en int → stocker dans values[i]
  3. Retourner le tableau complet

Le cast (int)ft_atol(...)

On a parsé en long et on stocke en int. Sans le cast explicite, le compilateur warn ("possible loss of precision"). Avec le cast, on dit "je sais ce que je fais, je veux tronquer".

Mais c'est safe ici parce qu'on a déjà validé via is_number que la valeur tient dans la plage int. Le cast ne perd donc aucune information.

Gestion d'erreur propre

Si un token est invalide en milieu de parcours, on libère values et on return NULL. Pas de leak, même en cas d'erreur partielle.

★ Pattern important : alloc + cleanup en cas d'erreur
tab = malloc(...);
for (i = 0; i < n; i++)
{
    if (problème)
    {
        free(tab);       // libérer avant de quitter
        return (NULL);
    }
    tab[i] = ...;
}
return (tab);
À chaque malloc doit correspondre un free sur tous les chemins, y compris les chemins d'erreur. C'est ce qui fait la différence entre du code "qui marche" et du code "sans leak".

5.10parse_args — l'orchestrateur

int *parse_args(int argc, char **argv, int *n)
{
    char    **tokens;
    int     *values;

    tokens = tokenize(argc, argv);
    if (!tokens)
        return (NULL);
    *n = count_tokens(tokens);
    if (*n == 0)
    {
        free_tokens(tokens);
        return (NULL);
    }
    values = convert_tokens(tokens, *n);
    free_tokens(tokens);
    if (!values)
        return (NULL);
    if (has_duplicates(values, *n))
    {
        free(values);
        return (NULL);
    }
    return (values);
}

Le flow

1. tokenize
argc + argv → char ** uniforme
↓
2. count_tokens
combien de nums on a ? Écrit dans *n
↓
3. Check *n == 0
cas argument vide ("" ou que des espaces)
↓
4. convert_tokens
tokens → int[] avec validation
↓
5. free_tokens
on n'a plus besoin des chaînes
↓
6. has_duplicates
check final, retourne NULL si doublon
↓
7. return values
tableau prêt pour build_stack

Le paramètre int *n en output

parse_args a besoin de retourner deux choses : le tableau de valeurs ET sa taille. Mais on ne peut retourner qu'une seule chose en C. Solution : on retourne le tableau, et on écrit la taille dans *n via un pointeur reçu en paramètre.

/* Appel depuis main */
int n;
int *values = parse_args(argc, argv, &n);   // on passe &n pour que parse_args puisse y écrire
// values = tableau, n = taille (modifié par parse_args)

C'est exactement le pattern qu'on a vu dans le Ch. 01 §1.13 (pass by pointer).

Cleanup à chaque étape

Note l'attention portée au cleanup :

  • Si tokenize rate → return NULL direct (rien à libérer)
  • Si count_tokens donne 0 → free tokens avant de return
  • Après convert_tokens → free tokens dans tous les cas (on n'en a plus besoin)
  • Si convert_tokens rate → return NULL (déjà libéré dedans)
  • Si doublons → free values avant de return

Chaque chemin d'exécution se termine avec 0 byte fuité. valgrind est content.

5.11Récap du chapitre

★ Pipeline du parser
argv → tokenize → char **tokens uniforme
tokens → count_tokens → n (taille)
tokens → convert_tokens (avec is_number + ft_atol) → int *values
values + n → has_duplicates → validation finale
Retour : int *values validé, n écrit via pointeur output
★ Les 8 fonctions et leur rôle
  • tokenize : argv → char ** uniforme (split si chaîne unique)
  • count_tokens : compte les éléments du char **
  • free_tokens : free le char ** (2 niveaux)
  • convert_tokens : char ** → int *, validation
  • parse_args : orchestrateur de tout ça
  • is_number : check format + plage int
  • is_valid_int : check format seulement (signe + chiffres)
  • ft_atol : conversion chaîne → long
  • has_duplicates : O(n²) check doublons
Auto-éval
Pourquoi on parse en long au lieu de int ?
Pour détecter les valeurs hors plage int. Si on parsait directement en int, "2147483648" (= INT_MAX + 1) ferait un overflow et on récupérerait silencieusement INT_MIN. En long, la plage est beaucoup plus large, donc on parse sans overflow puis on compare aux limites int pour valider.
Pourquoi free_tokens a 2 niveaux de free ?
Parce que tokens est un char ** : un tableau de pointeurs vers des chaînes. Chaque chaîne est mallocée séparément. Il faut donc d'abord free chaque chaîne (tokens[i]), puis le tableau lui-même (tokens). Sinon : memory leak (chaînes oubliées).
Que retourne parse_args en cas d'erreur ?
NULL. main teste si !values et affiche Error + exit 1 dans ce cas.
Pourquoi le paramètre int *n et pas int n ?
Parce qu'on veut retourner à main à la fois le tableau et sa taille. Comme C ne permet qu'une valeur de retour, on utilise un pointeur en paramètre output : parse_args écrit la taille via *n = ..., et main récupère via la variable qu'il a passée par &n.
