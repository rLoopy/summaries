chaque ligne du server expliquee

§7.1 — Vue d ensemble

server.c contient 3 fonctions et ~70 lignes :

  • handle_signal(int sig) — le handler appelé à chaque signal reçu
  • print_pid(void) — affiche le PID au démarrage (sans printf)
  • main(void) — setup sigaction puis boucle infinie sur pause()

§7.2 — handle_signal — le cœur du server

static void handle_signal(int sig)
{
    static unsigned char  c;
    static int            bit_count;

    c = c << 1;
    if (sig == SIGUSR2)
        c = c | 1;
    bit_count++;
    if (bit_count == 8)
    {
        if (c == 0)
            write(1, NEWLINE_STR, 1);
        else
            write(1, &c, 1);
        c = 0;
        bit_count = 0;
    }
}
★ Les variables static
Une variable static locale garde sa valeur entre les appels de la fonction. Sans static, c et bit_count repartiraient à 0 à chaque signal et on perdrait la reconstruction.
★ Auto-init à 0
En C, une variable static non initialisée est automatiquement initialisée à 0 par le standard. Pas besoin d écrire = 0.

Ligne par ligne :

  1. c = c << 1 : on décale tout d 1 cran à gauche. Position 0 libre pour le nouveau bit.
  2. if (sig == SIGUSR2) c = c | 1 : si SIGUSR2, on met 1 en position 0. Si SIGUSR1, on fait rien.
  3. bit_count++ : un bit de plus reçu.
  4. if (bit_count == 8) : caractère complet, on l affiche.
  5. if (c == 0) : char vaut 0 = fin de message, on affiche un saut de ligne.
  6. c = 0; bit_count = 0; : reset pour le prochain caractère.

§7.3 — print_pid — afficher sans printf

static void print_pid(void)
{
    pid_t pid;
    char  buf[12];
    int   i;

    pid = getpid();
    i = 0;
    while (pid > 0)
    {
        buf[i++] = (pid % 10) + DIGIT_ZERO;
        pid /= 10;
    }
    write(1, MSG_PREFIX, 12);
    while (i--)
        write(1, &buf[i], 1);
    write(1, NEWLINE_STR, 1);
}

Le sujet n autorise pas printf. On doit convertir le PID en string nous-mêmes avec write.

★ Pourquoi à l envers ?
La boucle remplit le buffer en partant des unités. PID 12345 devient buf = 5,4,3,2,1. Pour afficher dans le bon ordre, on parcourt en arrière avec while (i--).

Le + DIGIT_ZERO ('0' = 48 en ASCII) convertit un chiffre (ex: 5) en son caractère ASCII ('5' = 53). 5 + 48 = 53.

§7.4 — main — setup et attente

int main(void)
{
    struct sigaction sa;

    print_pid();
    sigemptyset(&sa.sa_mask);
    sigaddset(&sa.sa_mask, SIGUSR1);
    sigaddset(&sa.sa_mask, SIGUSR2);
    sa.sa_flags = SA_RESTART;
    sa.sa_handler = handle_signal;
    sigaction(SIGUSR1, &sa, NULL);
    sigaction(SIGUSR2, &sa, NULL);
    while (1)
        pause();
    return (0);
}
★ La séquence sigaction
  1. sigemptyset : vide le masque sa_mask.
  2. sigaddset SIGUSR1 + SIGUSR2 : ajoute les 2 au masque. Pendant un handler, ces signaux seront bloqués.
  3. sa.sa_flags = SA_RESTART : restart auto les syscalls interrompus. Pas d effet sur pause() mais défensif.
  4. sa.sa_handler = handle_signal : la fonction à appeler.
  5. sigaction(SIGUSR1, &sa, NULL) : enregistre pour SIGUSR1.
  6. Idem pour SIGUSR2.
  7. while(1) pause() : pause() bloque jusqu à un signal, handler tourne, pause() retourne, on recommence.
★ Pourquoi sigaddset les 2 signaux ?
Par défaut, sigaction bloque seulement le signal en cours pendant son handler. Mais nos 2 signaux modifient les MÊMES variables static. Sans sigaddset, un SIGUSR2 pourrait interrompre un handler SIGUSR1 et corrompre la reconstruction. On atomise.

§7.5 — Récap

★ Points clés
  • 3 fonctions : handle_signal, print_pid, main
  • Variables static dans handle_signal pour conserver l état
  • (c << 1) | bit : la formule de reconstruction
  • c == 0 = fin de message, on écrit un saut de ligne
  • sigaddset les 2 signaux pour atomiser le handler
  • while(1) pause() : attente sans CPU
  • Zéro variable globale
