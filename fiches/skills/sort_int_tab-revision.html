sort_int_tab
quick recap ↓

Bubble sort in place. void retour, 2 boucles imbriquées, 1 flag swaped.

🎯 l'algo en 4 points
  1. Guard : size < 2 → return ;. Protège contre le size - 1 underflow (size est unsigned).
  2. Init : swaped = 1 pour entrer dans le while extérieur au moins une fois.
  3. Passe : au début, swaped = 0 ET i = 0. Puis inner parcourt toutes les paires voisines, swap si mal ordonnées, swaped = 1 à chaque swap.
  4. Exit : si une passe complète ne touche à rien (swaped == 0) → le while extérieur sort. Trié.
💾 code final (commenté)
void sort_int_tab(int *tab, unsigned int size) { unsigned int i; int tmp; int swaped; /* Edge case : size 0 ou 1 → rien à trier. size est unsigned → size - 1 underflow à UINT_MAX si size==0. */ if (size < 2) return ; swaped = 1; while (swaped) { /* Reset par passe : doigt au début + carnet à NON. */ swaped = 0; i = 0; while (i < size - 1) { if (tab[i] > tab[i + 1]) { tmp = tab[i]; tab[i] = tab[i + 1]; tab[i + 1] = tmp; swaped = 1; } i++; } } }
🎨 patterns clés
  • Les 2 resets au même endroit : swaped = 0; i = 0; groupés en haut de la passe. Un reset = une passe indépendante. Les séparer = bug.
  • swaped = "est-ce que quelque chose a bougé pendant CETTE passe ?". Pas "sur la dernière paire". D'où le reset en HAUT, pas au milieu.
  • Swap en 3 temps via tmp : classique. Pas de XOR-swap, norm 42 n'aime pas.
  • i < size - 1 (pas i <= size - 1) : on compare tab[i] et tab[i+1], donc i+1 doit rester valide. La dernière paire comparée est (size-2, size-1).
  • Bubble sort = O(n²). Pas optimal mais trivial à écrire sans se tromper. L'exam ne demande pas mieux.
⚠️ les pièges
  • Oublier if (size < 2) return ; → size - 1 underflow unsigned à UINT_MAX quand size == 0 → boucle quasi-infinie + segfault en lisant hors tableau.
  • Mettre swaped = 0 DANS l'inner → se reset à chaque paire, perd son sens. Le flag ne veut plus dire "pendant la passe" mais "sur la dernière paire".
  • Oublier i = 0 au début de la passe → combiné au bug précédent : la 2e passe ne rentre plus dans l'inner, mais swaped reste à 1 (du dernier swap) → boucle infinie.
  • Comparer avec < au lieu de > → tri décroissant (ou pas de tri du tout selon l'input).
  • Return autre chose que void : le proto impose void. Tu modifies tab en place, rien à retourner.
  • Initialiser swaped = 0 → le while extérieur ne rentre jamais, le tableau n'est JAMAIS touché.
🧠 mental model
  • Analogie des livres : tu ranges tes livres par taille sur une étagère. Tu pointes 2 livres voisins, tu les échanges si mal ordonnés, tu avances. Arrivé au bout, tu recommences depuis le début tant que t'as bougé quelque chose.
  • Le carnet "j'ai bougé qqch" = swaped. On le remet à NON au DÉBUT de chaque tour, pas après chaque paire.
  • Le doigt qui avance = i. On le remet au DÉBUT de l'étagère au début de chaque tour.
  • Pourquoi ça finit forcément : à chaque passe, l'élément le plus grand "remonte" à sa place finale. En n passes max, tout est en place. Le swaped fait souvent sortir plus tôt.
  • Pattern réutilisable : "flag + reset top-of-loop" est le pattern standard pour "répéter jusqu'à stabilité" — utile aussi en relaxation, propagation, etc.
la règle d'or :
swaped = 0; i = 0; en HAUT de la passe, pas en bas.
plus if (size < 2) return ; en guard = zéro bug.
