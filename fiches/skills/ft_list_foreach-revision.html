ft_list_foreach
quick recap ↓

Parcours + callback. 4 lignes de code. L'exo le plus court du level 3.

🎯 l'algo en 3 points
  1. Walk : while (begin_list) — tant que le pointeur n'est pas NULL.
  2. Call : f(begin_list->data) — applique la fonction sur le data du node courant.
  3. Advance : begin_list = begin_list->next — saute au suivant. Le while gère automatiquement la sortie quand on arrive à NULL.
💾 code final
/* ft_list.h : à rendre AUSSI (sujet explicite) */ typedef struct s_list { struct s_list *next; void *data; } t_list; void ft_list_foreach(t_list *begin_list, void (*f)(void *)); /* ft_list_foreach.c */ #include "ft_list.h" void ft_list_foreach(t_list *begin_list, void (*f)(void *)) { while (begin_list) { f(begin_list->data); begin_list = begin_list->next; } }
🎨 patterns clés
  • Pointeur de fonction : void (*f)(void *) se lit "f est un pointeur vers une fonction qui prend un void * et retourne void". On l'appelle comme une fonction normale : f(arg). Même pattern que cmp dans sort_list.
  • NULL géré par le while : while (begin_list) = while (begin_list != NULL). Si la liste est vide au départ, on n'entre pas. Pas besoin d'un if séparé.
  • Passage par valeur : modifier begin_list dans la fonction ne change PAS la tête de liste de l'appelant. T'as une copie locale du pointeur, tu peux la réécraser tranquille.
  • void * = "pointeur vers n'importe quoi". La fonction f saura le caster. Ton ft_list_foreach s'en fout complètement du type réel.
  • Turn in 2 fichiers : ft_list_foreach.c ET ft_list.h. Le sujet est explicite. Le .h DOIT contenir la struct exactement comme donnée.
⚠️ les pièges
  • Oublier de rendre ft_list.h → fichiers manquants, fail auto.
  • Ordre des champs du struct différent → compile OK mais segfault au runtime : la main du tester écrit à offset 0 pensant que c'est next, ton code lit offset 0 pensant que c'est data. Random memory access = 💥. Copie la struct mot pour mot depuis le sujet.
  • Include <stdio.h> ou autre → Allowed functions: None. Aucune lib autorisée dans TON .c. Le tester fait l'import de son côté.
  • Ajouter un if (!begin_list) return ; → pas FAUX, mais redondant avec le while. Le jury pourrait considérer ça comme du bruit.
  • Modifier begin_list globalement → impossible, c'est local. Mais attention : si f modifie data (ex: *(int *)data *= 2), la liste de l'appelant EST modifiée (on passe le pointeur, pas une copie de la data).
🧠 mental model
  • Iterator + callback. Une des fonctions les plus utilisées en vrai dev (JS .forEach, Python for ... in, Rust iterators…). Une fois pigée, tu la reconnais partout.
  • ft_list_foreach ne sait rien de f. Elle promet juste : "je t'appelle sur chaque data". Décorrelation totale entre parcours et traitement.
  • Pattern pour lister les exos 42 utilisant un pointeur de fonction : sort_list (cmp), ft_list_foreach (f), ft_list_remove_if (cmp), ft_list_find... C'est le family de "fonctions d'ordre supérieur sur listes".
  • Si tu galères à lire void (*f)(void *) : mets le nom au milieu. "f est un * (pointeur) qui retourne void et prend (void *)". Puis généralise : type (*nom)(args) = pointeur vers une fonction qui...
la règle d'or :
while + f(data) + ->next. 3 mots, 1 fonction.
n'oublie pas ft_list.h avec la struct EXACTEMENT comme donnée.
