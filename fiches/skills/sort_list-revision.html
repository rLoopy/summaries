sort_list
quick recap ↓

Bubble sort sur liste chaînée. On swap les data, jamais les nœuds. !cmp(a, b) = "mal ordonné, faut swap".

🎯 l'algo en 5 points
  1. Guard : !lst || !lst->next → return (lst);. Liste vide ou 1 seul nœud = déjà triée.
  2. Init : swapped = 1 pour forcer l'entrée dans le while extérieur.
  3. Passe : au début, swapped = 0 ET cur = lst. Puis inner avance cur jusqu'à cur->next == NULL, en comparant la paire voisine.
  4. Swap data-only : si !cmp(cur->data, cur->next->data) → échange les ->data via tmp. Les ->next ne bougent jamais.
  5. Exit : passe sans swap → sort du while extérieur. Retourne lst (la tête n'a pas bougé).
💾 code final (commenté)
/* list.h fourni — NE PAS turn in */ #include "list.h" t_list *sort_list(t_list *lst, int (*cmp)(int, int)) { int swapped; int tmp; t_list *cur; /* Guard : liste vide ou 1 seul nœud → rien à trier. */ if (!lst || !lst->next) return (lst); swapped = 1; while (swapped) { /* Reset par passe : hypothèse rien ne bouge, cur repart de la tête. */ swapped = 0; cur = lst; while (cur->next) { /* cmp retourne !=0 si (a,b) bien ordonnés. !cmp(...) vrai → ordre cassé → swap data-to-data. */ if (!cmp(cur->data, cur->next->data)) { tmp = cur->data; cur->data = cur->next->data; cur->next->data = tmp; swapped = 1; } cur = cur->next; } } return (lst); }
🎨 patterns clés
  • Swap des data, PAS des nœuds. Relier des nœuds demande 4-5 pointeurs temp + gestion de la tête. Swapper ->data = 3 lignes, zéro risque.
  • La tête lst ne bouge JAMAIS avec cette approche. D'où return (lst); tout simple en sortie.
  • Reset en haut de passe : swapped = 0; cur = lst; groupés. Un reset = une passe indépendante.
  • Condition inner cur->next (pas cur) : on regarde la paire (cur, cur->next), donc cur->next doit exister. Sur le dernier nœud, cur->next == NULL → sort.
  • Avancée cur = cur->next TOUJOURS, swap ou pas. C'est l'équivalent du i++ de sort_int_tab.
🧭 lire la signature de cmp

Énoncé : cmp(a, b) != 0 si a, b sont dans le bon ordre. Donc la logique est inversée par rapport au réflexe "compare >".

exemple de cmpascendantdescendant
return (a <= b);✅ trie ↑✗
return (a >= b);✗✅ trie ↓

Règle mnémonique : !cmp(a, b) = "mauvais ordre → SWAP". C'est le seul point où on utilise cmp.

⚠️ les pièges
  • Oublier le ! devant cmp(...) → tri dans le mauvais sens (ou pas de tri). C'est l'erreur numéro 1 de cet exo.
  • Vouloir swapper les nœuds au lieu des data → 4 pointeurs à manipuler, risque de perdre la tête ou de faire des cycles. Ne le fais pas. Swap ->data, c'est l'idée clé.
  • Oublier if (!lst || !lst->next) return (lst); → segfault sur liste vide (lst->next déréf NULL).
  • Oublier return (lst); à la fin → warning de compile + valeur de retour indéfinie.
  • Condition inner while (cur) au lieu de while (cur->next) → sur le dernier nœud on déréférence cur->next->data (NULL) → segfault.
  • Mettre swapped = 0 dans l'inner → même bug que sort_int_tab : le flag perd son sens, potentielle boucle infinie.
  • Oublier cur = lst en haut de la passe → 2e passe : cur est resté sur le dernier nœud, l'inner ne rentre même pas. Et si swapped était à 1 → boucle infinie.
  • Avancer cur = cur->next uniquement en cas de no-swap → bug classique, on reste bloqué sur la même paire quand il y a swap.
🧠 mental model
  • Analogie train : les wagons (nœuds) sont attachés dans un ordre fixe. Mais les valises dedans (data), tu peux les bouger. Sort_list = déplacer les valises, laisser les wagons.
  • cmp = un arbitre qui te dit "ce couple est-il bien placé ?". Si non (retour 0) → tu échanges les contenus.
  • Pourquoi ça finit : à chaque passe, la plus grande valise "monte" d'un cran. En N passes max, tout est rangé. Le flag swapped fait souvent sortir plus tôt.
  • Différence vs sort_int_tab : même algo (bubble), mais i++ devient cur = cur->next, et size - 1 devient cur->next != NULL. Le flag + reset top-of-loop sont IDENTIQUES.
  • Complexité : O(n²) en temps, O(1) en mémoire. Exam valide, on s'arrête là.
la règle d'or :
!cmp(a, b) = mauvais ordre → swap ->data (pas les nœuds).
swapped = 0; cur = lst; en HAUT de la passe. return (lst);.
