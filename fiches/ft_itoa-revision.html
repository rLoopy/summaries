ft_itoa
quick recap ↓

int → char*. Malloc inside. INT_MIN trap géré avec un long.

🎯 l'algo en 6 gestes
  1. Setup : len=1, signe=1, n=nbr (en long).
  2. Cas 0 : early return "0" (evite les bugs du fill loop).
  3. Signe : si n<0, signe=-1, n=-n, len++.
  4. Count digits : while (tmp>=10) { len++; tmp/=10; }
  5. Malloc + fill right→left : result[i--] = n%10 + '0'; n/=10;
  6. Apply signe : if (signe==-1) result[0]='-'; puis return result;
💾 code final
#include <stdlib.h> char *ft_itoa(int nbr) { char *result; long n; long tmp; int len; int signe; int i; len = 1; signe = 1; n = nbr; if (nbr == 0) { result = malloc(2); if (!result) return (NULL); result[0] = '0'; result[1] = '\0'; return (result); } if (n < 0) { signe = -1; n = -n; len += 1; } tmp = n; while (tmp >= 10) { len++; tmp /= 10; } result = malloc(len + 1); if (!result) return (NULL); result[len] = '\0'; i = len - 1; while (n > 0) { result[i--] = n % 10 + '0'; n /= 10; } if (signe == -1) result[0] = '-'; return (result); }

⚠️ les pièges
  • INT_MIN overflow : -(-2147483648) en int = UB. Fix : long n = nbr → -n marche (long contient ±9.2×10¹⁸).
  • Cas nbr = 0 : sans early return, le fill loop while (n>0) ne rentre jamais, result[0] reste uninit.
  • Count digits AVANT malloc : tu peux pas malloc sans connaître la taille. D'où le tmp = n; while (tmp>=10).
  • Préserver n pendant le count : utilise tmp, ne détruis pas n → il sert pour le fill.
  • result[len] = '\0' AVANT fill : pose le terminator UNE fois, le fill part de i = len - 1 (position juste avant).
  • Ordre du malloc-check : result = malloc(...) PUIS if (!result) return NULL, jamais l'inverse.
  • Conversion digit ↔ char : + '0' pour int → char, - '0' pour char → int (miroir atoi).
la règle d'or :
construire la string À L'ENVERS (n % 10 donne le dernier digit).
signe en dernier, '\0' en premier, tout le reste au milieu.
