count_pec : 2 versions comparees

version actuelle (4 passes) vs version proposee (1 passe)

Le probleme a resoudre

Pour valider une map, on doit compter combien de P, E, C elle contient. Et trouver la position du joueur. Les 2 versions font ca, mais differemment.

Versus cote a cote

V1 - Actuelle (4 passes)

static int count_char(t_game *g, char c) { int count = 0; // double boucle // si map[y][x] == c -> count++ return (count); } static void find_player(t_game *g) { // double boucle // si map[y][x] == 'P' -> sauve px, py } void count_pec(t_game *g) { int p = count_char(g, 'P'); // pass 1 int e = count_char(g, 'E'); // pass 2 int c = count_char(g, 'C'); // pass 3 if (p != 1 || e != 1 || c < 1) error_exit(g, ...); g->c_total = c; find_player(g); // pass 4 }
4 passes 3 fonctions noms clairs

V2 - Proposee (1 passe)

static void check_cell(t_game *g, int x, int y, int *counts) { if (g->map[y][x] == 'P') { counts[0]++; g->px = x; g->py = y; } else if (g->map[y][x] == 'E') counts[1]++; else if (g->map[y][x] == 'C') counts[2]++; } void count_pec(t_game *g) { int counts[3]; // [0]=P [1]=E [2]=C // double boucle, check_cell sur chaque if (counts[0] != 1 || counts[1] != 1 || counts[2] < 1) error_exit(g, ...); g->c_total = counts[2]; }
1 passe 2 fonctions counts[] indexe

Verdict

V2 est meilleure sur quasi tous les criteres. Le seul inconvenient (counts[0/1/2] indexe) est mineur : un commentaire a cote du tableau le rappelle.

Pourquoi V1 a un defaut majeur : la question "pourquoi 4 passes ?" en defense est legitime. Et la reponse honnete c est "c est moins efficace, j aurais du faire en 1 passe". Donc autant le faire bien des maintenant.
Astuce memoire : commentaire au-dessus de la declaration -> int counts[3]; /* [0]=P [1]=E [2]=C */
Si on te demande counts[1], tu pointes ton commentaire.
