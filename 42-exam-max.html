Code final

Compile avec -Wall -Wextra -Werror, tous tests OK

max.c 
int  max(int* tab, unsigned int len)
{
    unsigned int i = 0;
    if (len == 0)
        return 0;
    int max = tab[i];
    while (i < len)
    {
        if (tab[i] > max)
            max = tab[i];
        i++;
    }
    return (max);
}

2

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Pourquoi int max = 0 est dangereux ?
Pense aux nombres négatifs...

Si le tableau contient uniquement des négatifs {-5, -3, -1}, aucun élément ne sera > 0, donc on retourne 0 qui n'est pas dans le tableau. Init avec tab[0].

+
Quelle diff entre while(tab[i]) et while(i < len) ?
String vs tableau d'int...

while(tab[i]) s'arrête quand la valeur vaut 0 — pour les strings terminées par \0. Un tableau d'int peut contenir des 0 légitimes. Utilise i < len.

+
Pourquoi comparer avec max et pas tab[i+1] ?
Deux raisons...

1) tab[i+1] déborde au dernier élément (undefined behavior). 2) Comparer des voisins ne garde pas trace du maximum global.

+
Pourquoi unsigned int i et pas int i ?
Le compilateur te le dit...

-Wsign-compare + -Werror = compile pas. Le compteur doit matcher le type de len (unsigned).

+
Que se passe-t-il si on lit tab[0] avant de check len == 0 ?
Tableau vide...

Tableau vide + tab[0] = lecture d'adresse invalide = segfault. Toujours vérifier les cas limites AVANT d'accéder aux données.

Pièges déjoués

7 pièges — chaque carte = une leçon gravée

BOUCLE
PIÈGE #1
✕while (tab[i])
✓while (i < len)
Le piège : confondre string (\0) et tableau d'int (len). while(str[i]) = strings uniquement.
BOUCLE
PIÈGE #2
✕while (tab[i] < len)
✓while (i < len)
Le piège : confondre valeur et index. tab[i] = contenu. i = position.
LOGIQUE
PIÈGE #3
✕max = tab[i]; (sans if)
✓if (tab[i] > max) max = tab[i];
Le piège : écraser l'accumulateur à chaque tour sans condition.
LOGIQUE
PIÈGE #4
✕if (tab[i] < tab[i+1])
✓if (tab[i] > max)
Le piège : comparer des voisins au lieu de l'accumulateur. tab[i+1] déborde au dernier élément.
INIT
PIÈGE #5
✕int max = 0;
✓int max = tab[0];
Le piège : 0 bat tous les négatifs. Toujours init avec un vrai élément du tableau.
SÉCURITÉ
PIÈGE #6
✕int max = tab[i]; // avant check
✓if (len == 0) return 0; // PUIS tab[i]
Le piège : accéder aux données avant de vérifier qu'elles existent. Tableau vide = crash.
TYPE
PIÈGE #7
✕int i = 0; vs unsigned int len
✓unsigned int i = 0;
Le piège : -Wsign-compare + -Werror. Le compteur matche le type de len. L'accumulateur reste int.

Pattern réutilisable

Parcours + accumulateur — min, max, sum, search, count...

  1. Gérer le cas vide len == 0 en premier
  2. Initialiser l'accumulateur avec tab[0] — jamais une valeur arbitraire
  3. Parcourir avec i < len — l'index, pas la valeur
  4. Comparer tab[i] avec l'accumulateur — jamais tab[i+1]
  5. Return l'accumulateur
