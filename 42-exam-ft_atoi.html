ft_atoi.c 
int     ft_atoi(const char *str)
{
    int i = 0;
    int res = 0;
    int signe = 1;

    while ((str[i] >= 9 && str[i] <= 13) || str[i] == 32)
        i++;
    if (str[i] == '+' || str[i] == '-')
    {
        if (str[i] == '-')
            signe = -1;
        i++;
    }
    while (str[i] >= '0' && str[i] <= '9')
    {
        res = res * 10 + (str[i] - '0');
        i++;
    }
    return (res * signe);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Pourquoi >= 9 et <= 13 pour les whitespaces ?
Qu'est-ce qu'il y a entre 9 et 13 en ASCII ?

Les codes ASCII 9 à 13 correspondent aux whitespaces invisibles : \t (9), \n (10), \v (11), \f (12), \r (13). Plus simple que de les écrire un par un avec ||. L'espace normal ' ' est à 32, il faut l'ajouter séparément.

+
Pourquoi if et pas while pour le signe ?
Que se passe-t-il avec "--42" ?

atoi ne lit qu'un seul signe. Avec while, la string "--42" flipperait le signe deux fois et donnerait 42 au lieu de 0. Avec if, on lit un seul - ou + et c'est tout.

+
Que fait res * 10 + (str[i] - '0') ?
Avec "42", que vaut res à chaque tour ?

* 10 décale les chiffres existants à gauche (4 → 40). str[i] - '0' transforme le char en int ('2' = 50, '0' = 48, diff = 2). + pose le nouveau chiffre à droite (40 + 2 = 42). Mantra : "je décale, je pose".

+
Pourquoi le i++ du bloc 2 est en dehors du if interne ?
Qu'est-ce qu'on fait si c'est un '+' ?

Le i++ doit s'exécuter que ce soit '-' ou '+'. Si c'est '+', on ne change pas signe (il reste à 1), mais on doit quand même avancer pour ne pas lire le '+' comme un chiffre.

+
'0' vs 0 — c'est quoi la différence ?
Un piège classique...

'0' avec quotes = le caractère zéro, qui vaut 48 en ASCII. 0 sans quotes = le nombre zéro (aussi '\0', le null byte). Comparer à 0 au lieu de '0' dans le bloc 3 = le code accepte n'importe quoi comme chiffre.

Pièges déjoués

4 pièges rencontrés sur cet exo

SYNTAXE
PIÈGE #1 — Parenthèses && / ||
✕str[i] >= 9 && str[i] <= 13 || str[i] == 32
✓(str[i] >= 9 && str[i] <= 13) || str[i] == 32
Le piège : -Werror refuse de compiler si && et || sont mélangés sans parenthèses. Le compilateur n'est pas sûr de ton intention. Toujours grouper avec ().
TYPES
PIÈGE #2 — '0' vs 0
✕str[i] >= 0 && str[i] <= 9
✓str[i] >= '0' && str[i] <= '9'
Le piège : 0 = null byte (ASCII 0). '0' = caractère zéro (ASCII 48). Sans les quotes, la condition accepte quasi tout et le nombre explose.
LOGIQUE
PIÈGE #3 — while vs if pour le signe
✕while (str[i] == '+' || str[i] == '-')
✓if (str[i] == '+' || str[i] == '-')
Le piège : atoi ne lit qu'un seul signe. while lirait "--42" en flippant le signe 2 fois → résultat faux. Toujours if, jamais while.
SYNTAXE
PIÈGE #4 — Bloc 1 : espace oublié
✕str[i] >= 9 && str[i] <= 13 seulement
✓(...) || str[i] == 32 ou str[i] == ' '
Le piège : l'espace ' ' (ASCII 32) n'est pas dans la range 9-13. Il faut l'ajouter avec ||. Sans ça, " 42" ne skip pas les espaces.

Pattern réutilisable

Conversion string → nombre — atol, strtol, base conversion...

  1. Skip whitespace : while tant que c'est un espace ou 9-13
  2. Gérer le signe : if (pas while), stocker dans une variable, avancer i++
  3. Construire le nombre : res = res * 10 + (str[i] - '0') — décale + pose
  4. Appliquer le signe : return (res * signe)
