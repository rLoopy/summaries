ft_strcspn.c 
#include <stddef.h>

size_t	ft_strcspn(const char *s, const char *reject)
{
	int i = 0;
	int j = 0;
	while (s[i])
	{
		while (reject[j])
		{
			if (s[i] == reject[j])
				return (i);
			j++;
		}
		j = 0;
		i++;
	}
	return (i);
}

Flashcards

Réponds dans ta tête AVANT de cliquer

+
Que retourne strcspn ?
Complémentaire de strspn...

Le nombre de caractères au début de s qui ne sont pas dans reject. C'est l'indice du premier char de s qui appartient à reject.

+
Que retourne strcspn("hello", "xyz") ?
Aucun char de "hello" n'est dans "xyz"...

5 — aucun caractère de "hello" n'est dans "xyz", donc on parcourt toute la string. La fonction retourne la longueur totale de s.

+
Que retourne strcspn("hello", "h") ?
Le premier char matche direct...

0 — le premier caractère de "hello" est 'h' qui se trouve dans reject. Match immédiat → on retourne i = 0.

+
Pourquoi reset j = 0 après la boucle interne ?
Que se passerait-il sinon ?

Sans le reset, j continuerait depuis sa position précédente pour le prochain char de s. On ne parcourrait reject qu'une seule fois au total, ratant des matchs → résultat faux.

+
Quel header faut-il pour size_t ?
Pas stdlib.h cette fois...

stddef.h — c'est là que size_t est défini (type non signé pour les tailles). On peut aussi utiliser stdlib.h ou string.h qui l'incluent indirectement, mais stddef.h est le plus explicite.

Pièges déjoués

4 pièges — chaque carte = une leçon gravée

BOUCLE INFINIE
PIÈGE #1
✕while (reject[j]) { if (s[i] == reject[j]) return(i); }
✓if (s[i] == reject[j]) return(i); j++;
Le piège : oublier j++ dans la boucle interne provoque une boucle infinie. L'index j reste à 0 et compare indéfiniment s[i] avec reject[0].
RESET OUBLIE
PIÈGE #2
✕// pas de j = 0 après la boucle interne
✓j = 0; i++; // après while(reject[j])
Le piège : sans j = 0, reject n'est parcouru qu'une seule fois pour toute la string. Pour le deuxième char de s, la boucle interne commence déjà à la fin de reject → jamais de match.
RETURN FINAL
PIÈGE #3
✕// oubli du return i après la boucle externe
✓return (i); // après while(s[i])
Le piège : si aucun char de s ne se trouve dans reject, la boucle externe se termine sans retourner. Il faut return (i) à la fin — i vaut alors la longueur totale de s.
SIZE_T
PIÈGE #4
✕// pas de #include <stddef.h>
✓#include <stddef.h>
Le piège : size_t est dans le prototype. Sans stddef.h, le type est inconnu et le code ne compile pas. C'est un oubli fatal à l'exam.

Pattern réutilisable

Boucle imbriquée avec reset — ft_strpbrk, inter, union, strspn

  1. Boucle externe sur s avec index i : tant que s[i] != '\0'
  2. Boucle interne sur reject avec index j : tant que reject[j] != '\0', avec j++
  3. Si s[i] == reject[j] → match trouvé : return (i) immédiatement
  4. Après la boucle interne : reset j = 0 puis incrémenter i++
  5. Si la boucle externe se termine sans match : return (i) (longueur totale de s)
OÙ RÉUTILISER CE PATTERN
ft_strpbrk — variante : retourner s + i (pointeur) au lieu de i
ft_strspn — inverse : continuer tant que s[i] est DANS accept (pas dans reject)
inter / union — même logique pour vérifier l'appartenance d'un char à un set
ft_strtok — utilise strcspn/strspn en interne pour trouver les délimiteurs

Évolution du code

VERSION 1 — structure OK, 3 bugs
size_t ft_strcspn(const char *s, const char *reject) { int i = 0; int j = 0; while (s[i]) { while (reject[j]) { if (s[i] == reject[j]) return (i); // BUG 1 : oubli j++ ← boucle infinie ! } // BUG 2 : oubli j = 0 ← reject parcouru qu'une fois i++; } // BUG 3 : oubli return i ← undefined behavior }
pas de j++ → boucle infinie dès que reject[j] != '\0'
pas de j=0 → reject parcouru une seule fois pour toute la string
pas de return i final → undefined behavior si aucun match

size_t ft_strcspn(const char *s, const char *reject) { int i = 0; int j = 0; while (s[i]) { while (reject[j]) { if (s[i] == reject[j]) return (i); j++; // FIX 1 ✓ } j = 0; // FIX 2 ✓ i++; } return (i); // FIX 3 ✓ }
j++ dans la boucle interne ✓

Indice : même double boucle, mais la logique s'inverse — continuer tant que le char IS dans accept.

Indice : pour chaque char de s1, parcourir s2 pour vérifier s'il y est — exactement le même pattern de double boucle avec reset.
